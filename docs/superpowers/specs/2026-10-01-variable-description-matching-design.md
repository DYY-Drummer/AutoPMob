## 1. 目的と成功基準

**背景**: 本研究と式の組合せ法（Kato and Kano 2025, 09-27 報告の [9]）との違いを「文脈を扱えること」に置いている。しかし、第 2 段の並べ直しで効いていたのは変数の重複率に基づく特徴量で、文脈の近さはほとんど効かなかった（PFI・アブレーション）。一因は、評価ケースが入出力変数を正解式と同じ記号で与えていることにある（全ケースの入出力変数が正解式の変数記号に含まれる）。実際には、利用者は文献の記号を知らないことがあり、同じ記号が別の量を指すこともある（DB で異なる説明の数は n が 238 通り、A が 229 通り、T が 171 通り）。

**問い**: 式の変数を記号ではなく自然言語の説明で表し、変数の重複率などの特徴量を説明どうしの意味の近さで測った場合に、

1. **置き換え**: 記号を使わない照合で、記号による照合と同程度の精度が出るか。
2. **頑健性**: 利用者が文献と違う記号で変数を書いたとき、記号による照合はどこまで下がり、説明による照合は保てるか。

**成功基準**（作業が完了したと言える条件。結果の良し悪しではない）

1. 設定 A の 1,823 ケースすべてについて、記号なしの説明文・変数の言い換え・別の記号を API で生成し、品質の確認（§3.2）を通す。自動の確認で残った不合格は件数と ID を記録する。

### 3.1 条件

| 条件 | 照合 | 説明文 | 入出力変数 | 役割 |
|---|---|---|---|---|
| S0 | 記号 | 元のまま | 文献の記号 | 既報（設定 A・w30-70 で R@K 0.780）の再現 |
| S1 | 記号 | 記号なしに書き直したもの | 文献の記号 | 記号版の基準 |
| S1-r50 / S1-r100 | 記号（S1 で学習した模型） | 記号なし | テストケースだけ、入出力の 50% / 100% を `alt_symbol` に替える | 頑健性 |

### 3.2 `make_var_descriptions.py`（ケース側のデータ生成）

- **入力**（1 ケース 1 リクエスト）: ケースの説明文と、入出力変数ごとの「正解式の中でのその記号の説明」（正解式が複数あれば重複を除いて全部）と、入力か出力かの区別。式の LaTeX と式の ID は渡さない。
- **出力**（`output_config.format` の JSON スキーマで固定する）:
  - `context_nosym`: 記号の言及を普通の言葉に置き換えた説明文。それ以外の情報は足さない。
  - `variables`: 配列。各要素は `{symbol, paraphrase, alt_symbol, meaning_conflict}`。
    - `paraphrase`: 利用者が自分の言葉で書いたような説明。記号を使わない、元の言い回しを写さない、単位を書かない。量を区別する限定語（入口・ジャケットなど）は残す。
    - `alt_symbol`: 別の教科書や技術者が使いそうな記号。元の記号とも、同じケースの他の入出力変数の記号や `alt_symbol` とも重ならない。
    - `meaning_conflict`: 渡した説明が別々の量を指している場合に true。このときは最初の説明の量で `paraphrase` を書く。多出典ケースでは記号の一致で式を組んだため、同じ記号が別の量を指すことがあり、その件数を測るために使う。
- **送り方**: まず通常の API で 20 件を試し、品質とトークン数を確かめて、バッチの料金を見積もり直して報告する。了承を得たら、残りを Message Batches API で送る。拒否（`stop_reason: "refusal"`）や失敗のケースは、通常の API で再実行する。
- **品質の確認**（全件。不合格のケースは最大 2 回作り直す）:
  1. **記号が残っていない**: 出力に `$ \ _ ^ { }` が含まれず、2 文字以上の記号が単語として現れないこと。1 文字の記号が単独の語として現れたら目視で確かめる（英語の冠詞 a と衝突するため）。
  2. **写していない**: 正規化（小文字化、角括弧の単位と句読点の除去）した言い換えが、元の説明と一致しないこと。元の説明との単語の重なり（Jaccard）と E5 類似度の分布も記録する。
  3. **区別できている**: 同じケースの中で言い換えが重複しないこと。`alt_symbol` の条件（上記）を満たすこと。
  4. **対応が正しい**: 返ってきた `symbol` の集合が、渡した入出力変数の集合と一致すること。
  5. **意味が保たれている**: 無作為に選んだ 50 変数を CSV に出す。私が読み、元の量と違う意味になっている誤りの件数を報告する（本人も同じ CSV で確かめられる）。
- **D0**: LLM は使わない。正解式（`correct_model_ids` の順）のうち、その記号を最初に含む式の説明をそのまま写す。
- **規模と料金の目安**: 入力は約 1.2k トークン×1,823 件。出力は思考を含めて約 1〜2k トークン×1,823 件。バッチの料金は Opus 5.5（入力 $2・出力 $10／100 万トークン）で約 23〜41 ドル。単価は 2026-09-25 時点の API 資料の値で、試行 20 件の実測で見積もり直す。
- **生成したモデルの記録**: 通常の API での試行と再実行には、拒否されたときに別のモデルで再実行するサーバ側のフォールバック（`fallbacks: "default"`）を付ける。バッチでは使えない。そのため、各ケースを実際に生成したモデル名（応答の `model`）を `var_descriptions.json` に記録し、指定と違うモデルで作られたケースの数を報告する。

### 3.3 本実験の前の確認（`analyze_var_description.py --precheck`）

- 設定 A の全ケースから組を作り、E5 の類似度で「同じ変数」と「同じ式の中の別の変数」をどれだけ分けられるかを AUC で測る（正例・負例の定義は §3.4 の τ と同じ）。これは診断で、τ の決定には使わない。
- 間違えやすい組（類似度が最も高い負例と最も低い正例、各 20 組）を保存し、考察に使う。
- **AUC が 0.80 未満なら、本実験に進む前に報告して相談する。** 汎用の埋め込みでは近い量（反応器温度と入口温度など）を区別できないという結果も、1 つの知見になる。

### 3.4 `var_matching.py`（照合と特徴量）

- **埋め込み**: DB の説明 27,994 件（抽出したまま、前処理なし）、言い換え、D0 の写した説明。`external_baselines.embed_texts` とキャッシュ（`experiments/embeddings/`）を流用する。
- **同じ変数の判定**: コサイン類似度 ≥ τ。
- **τ の決め方**: seed ごとに、その seed の学習用ケースだけから組を作る。
  - 正例: 言い換え（D0 では写した説明）と、正解式の中の同じ記号の説明との組。
  - 負例: 同じ正解式の中の別の記号の説明との組。近いが別の量を区別するという、一番難しい誤りをちょうど表す。
  - Youden の J（真陽性率 − 偽陽性率）が最大になる τ を選び、seed ごとに記録する。
- **1 対 1 の対応**: ケースの入出力 Q と式の変数 V について、τ 以上の組を辺にした二部グラフの最大マッチング M（Hopcroft–Karp、`scipy.sparse.csgraph.maximum_bipartite_matching`）を取る。|M| が記号版の |Q∩V| に当たる。完全一致の照合なら両者は厳密に等しい。
- **特徴量**（reranker-10S の 10 列）:

| 列 | 記号版 | 説明版 |
|---|---|---|
| f0 文章類似度（TF-IDF） | 説明文 vs 式の文章 | 同じ（説明文は条件の版） |
| f1 Jaccard | \|Q∩V\| / \|Q∪V\| | \|M\| / (\|Q\| + \|V\| − \|M\|) |
| f2 SVD 類似度 | 照会文 = 説明文 ＋ 入出力記号の列 | 照会文 = 説明文 ＋ 入出力の表し方の列（記号・付け替えた記号・言い換え・写した説明のどれか） |
| f3 / f4 入力・出力の被覆 | 式に現れる入力・出力の割合 | M で対応がついた入力・出力の割合 |
| f5 特化度 | \|Q∩V\| / \|V\| | \|M\| / \|V\| |
| f6 分野の一致 | 説明文に分野名を含むか | 同じ（説明文は条件の版） |
| gComp | (V∩Q) のうち参照集合の変数の和集合にないものの数 / \|Q\| | M で対応がつき、参照集合（第 1 段の上位 5 件、自身を除く）のどの変数とも τ 未満である Q の数 / \|Q\| |
| gCoh | V のうち参照集合の和集合にあるものの割合 | V のうち、参照集合のいずれかの変数と τ 以上になるものの割合（式どうしの説明を照合） |
| gDom | 参照集合と分野が同じ割合 | 同じ |

- **第 1 段の変数の重複率**: 全 11,146 式に対して計算するので、|M| の代わりに min(対応先のある Q の数, 対応先のある V の数) を使う。この値は |M| の上限で、ケースごとの類似度行列（|Q| × 58,008）を式ごとに集約すればベクトル演算で計算できる。上位 50 件について、近似と厳密な |M| が食い違う割合を測って報告する。
- **τ への感度**: 設定 A・seed 42 で、D1 の τ±0.02 の R@K も測る。

### 3.5 `run_var_description.py`（学習と評価）

- seed ごとに、層化分割 → （説明版なら τ を決める）→ 全ケースの第 1 段の候補を計算 → 特徴量を 1 回だけ計算 → 学習 → テストケースで評価する。
- 学習ループは `set_aware_reranker.run_mode` と同じ順序で乱数を消費する（`rng.shuffle(tr)`、`rng.sample(neg, ns)`、torch の seed）。そうすれば、S0 で既報と同じ値が再現する。
- S1 の模型は、S1（p=0）・S1-r50・S1-r100 のテストケースで評価する。各テストケースで付け替える変数の数は ⌈p × 入出力変数の数⌉ とする。どの変数を替えるかは case_id から決まる固定の乱数で選ぶので、どの seed でも同じになる。
- 出力は strat_A.json と同じ形（`results[条件]` に各指標の `{mean, std}` と `per_seed`）にする。`--save-per-case` で、族別の内訳のためにケースごとの値も保存する。

### 3.6 `analyze_var_description.py`（検定と図）

- 対応あり検定は `analyze_significance.paired_stats`（Wilcoxon 符号順位・対応あり t・Cohen の d_z、10 seed）で行う。指標は R@K・MAP・Recall@20。
- 族別の R@K の内訳を、ケースごとの値から出す（単一出典 = original、多出典 = multisource_*、合成 = dae_*）。
- 図: 横軸に記号を替えた割合（0/50/100%）、縦軸に R@K を取る。S1 を線で、D1 を水平線と帯で、D0 を破線で描く。設定 A と B の 2 枚組とし、エラーバーは 10 seed の平均 ± SD、キャプションは英語にする。

## 4. テスト（pytest）

1. 完全一致の照合を入れると、新しい特徴量（f1・f3・f4・f5・gComp・gCoh）が既存の `compute_features_with_set` の値と一致する（実ケース 20 件 × 候補 50 件）。
2. 最大マッチング: q1 と q2 がどちらも v1 にだけ近ければ |M| = 1。貪欲法では 1 本しか取れない交差の例でも 2 本を返す。
3. 第 1 段の近似: 各 q の辺が 1 本以下なら |M| と一致し、一般には |M| 以上になる（小さな乱数行列で確かめる）。
4. τ の決め方: 分離できるおもちゃのデータで、τ が 2 群の間に入る。
5. 付け替え: p=0 は元のまま、p=1 はすべて替わる。同じ case_id なら毎回同じ変数が選ばれる。
6. 記号の漏れの検出器: `$T$`・`T_{in}`・`\alpha` を検出し、普通の英文は通す。
7. 回帰の確認（実データ、遅いテスト）: S0・設定 A・seed 42・w30-70 で R@K = 0.8403（許容 1e-4）。

## 5. 実行の順番と結果の読み方

**順番と確認点**

1. 試行 20 件 → 料金を見積もり直して報告し、了承を得る → バッチで生成 → 品質の確認。
2. 本実験の前の確認（AUC が 0.80 未満なら相談）。
3. 本実験（設定 A・B）→ 分析と図 → `development_log.tex` に追記。

**比較**（10 seed の対応あり）: D1 vs S1（置き換え）、S1-r50・S1-r100 vs S1（頑健性）、S1-r100 vs D1、D0 vs D1（漏れ）、S1 vs S0（説明文から記号を消した影響）。

**結果の読み方**（結果を見る前に決めておく）。「有意」は、対応あり t 検定と Wilcoxon 符号順位検定の両方で p < 0.05 の場合に限る。信頼区間は、10 seed の差に t 分布を当てはめた 95% 区間とする。

- **置き換え**（D1 − S1 の R@K）
  - 差の 95% 信頼区間が ±0.02 に収まれば、「記号を使わなくても同程度」と書く。
  - D1 が有意に低ければ、差の大きさと、負ける族や量（近いが別の量など）を、間違えやすい組と族別の内訳で示す。
  - D1 が有意に高ければ、記号の多義性の解消が効いた可能性として書き、多義的な記号（n・A・T など）を含むケースで確かめる。
- **頑健性**: S1 の低下が検定で有意な場合に限り、「記号による照合は、利用者の記号が文献と一致することに依存する」と書く。D1 は記号を使わないので、構成上この影響を受けない。図ではこの点を明記する。
- **D0**: 手法の性能としては報告しない。漏れの大きさとしてだけ示す。
- **`meaning_conflict`**: 該当する変数が 5% を超えたら、該当ケースを除いた比較も添える。
- **位置付けの書き方**: 変数の説明を「文脈」と呼ぶか、[9] との違いをどう書くかは、結果を見てから本人と決める。変数の定義で同じ量かを判定する点は研究室の ProcessBERT と重なることを明記し、先行研究に実在しない違いは作らない。

## 6. スコープ外

- 記号と説明の併用（精度改善の検証）
- PFI・アブレーション（説明版で、どの特徴量が効くか）
- 自由度ゼロ停止・貪欲選択
- E5 以外の埋め込みモデルと ProcessBERT の比較（`--model` で差し替えられる実装にはする）
- ゼミ報告・修論への反映（結果を見てから別の作業として行う）
