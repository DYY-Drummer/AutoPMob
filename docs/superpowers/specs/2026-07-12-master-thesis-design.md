## 3. 執筆方法論（指定 2 記事の適用）

- **shunk031「アウトラインを書こう」**: 各章を 3 階層で骨子化する。トピックセンテンス（段落の主張、章あたり 3〜6 本）→ サポート文（各 2〜3 本、**根拠となる図・表・数値・実験スクリプトを紐付ける**）→ 小結論。骨子を承認してから本文化する。
- **Kotoba Tech（笠井）論文執筆ガイド**: Figure 1 を 1 ページ目に置く。冒頭 2 段落で問題への共感を作る。Intro 末尾に章ロードマップを置き、以降のセクションは「驚きなし」で予告どおり進める。Related Work は列挙でなく毎回「本研究との相違」に戻る。抽象→具体の順で段落を書く。図表キャプションは自己完結にする。Abstract は最後に書き直す。

## 4. タイトル

- 英語: **Equation-Set Retrieval Using Equations and Context Extracted from the Literature for Automated Physical Model Building**
- 日本語（表紙用）: **文献から抽出した数式と文脈を用いた物理モデル自動構築のための数式集合検索**
- 改訂履歴: T1（Set-aware ... from Multiple Documents、2026-07-12）→ L2（Context- and Set-aware ... from the Literature、2026-07-13）→ **V1（現行、2026-07-13）**。本人の意図＝「文献から抽出した数式」と「文脈」の明示。主題は過大主張を避け「数式集合検索」に固定（構築は目的句）。「集合考慮（set-aware）」はタイトルから外れたが第3章名と貢献2で担保。

選定理由: 手法の核心（set-aware＝式を単独でなく集合として評価する特徴量）と AutoPMoB の文脈（複数文献からの情報再構成）の両方を含み、研究室の過去タイトル（…among Multiple Documents）の系譜に乗る。

## 5. 章構成と各章のストーリー（レベル 0 アウトライン）

7 章構成。データセット構築は作業量・貢献の大きさから独立章とする（過去修論の 6 章構成からの意図的な変更）。

### 第 1 章 Introduction

1. 物理モデルはプロセス産業のデジタルツイン・設計・運転に不可欠だが、構築には膨大な文献調査と試行錯誤を要する（研究室の伝統的導入）。
2. AutoPMoB 構想の説明。本研究のサブタスク＝「説明文＋入出力変数から、モデルを構成する数式の集合を複数文献由来の DB から検索する」。文章類似度だけでは足りない理由＝物理モデルは変数を共有し連立して初めて解ける系だから。
3. 貢献 3 点: (1) 11,146 式 DB＋解けることを保証した DAE ケース生成＋層化分割、(2) 集合特徴量による 2 段階検索で Recall@K +0.22（古典 IR・LLM 直接生成の両方に優位）、(3) 機構の実証→学習版 greedy→自由度ゼロでの自己停止。
4. Figure 1（AutoPMoB 全体像と本研究の位置づけ）＋章ロードマップ。

### 第 2 章 Related Work

4 系統: (a) AutoPMoB 要素技術の先行研究（ProcessBERT 等）、(b) 情報検索と再順位付け（相違: 独立に関連する項目でなく連立する集合を返す）、(c) LLM による科学知識の直接生成（外部比較対象としての位置づけ）、(d) 数式検索・数学情報検索（相違: 単式の類似検索であり解ける系の検索ではない）。各系統の末尾で本研究との相違に戻る。

### 第 3 章 手法: Set-aware Equation-Set Retrieval

1. 問題定式化: 入力 q =（説明文, 入力変数, 出力変数）、出力＝DB 中の数式の順位付き集合。「解ける系」＝方程式数と未知数の数が一致（自由度ゼロ）をここで定義。
2. 第 1 段: 7 特徴量（文章・変数類似度）による候補絞り込み。
3. 第 2 段: 集合特徴量 3 個（補完性・一貫性・ドメイン一致）を加えた 10 特徴量＋MLP による逐次的な並べ直し（reranker-10S）。
4. 逐次選択の 3 方式: 静的スコアリング／推論時 greedy／学習版 greedy（teacher forcing で訓練時も逐次文脈を与える）。
5. 自由度による自己停止（DoF-stop）: K を知らずに系が閉じた時点で停止し、解ける系を返す。

### 第 4 章 データセット: Equation Database and Test Case Construction

1. 数式 DB: 論文 329 報からの LLM（Gemini 2.5 Pro）抽出＋32 分野の基礎式 670 式＋表記正規化 → 11,146 式・361 ソース。
2. ケース 2,838 件の内訳（オリジナル 92・規則ベース複数文献 731・DAE 1,000・データ拡張 1,015）。データ拡張ケース（無作為入替・言い換え）は訓練に用い、主要評価（設定 A・B）からは除外（拡張込みの評価は baseline 水増しを示す比較としてのみ提示）。
3. DAE ケース生成手順（加藤先生の手順: ODE を種に変数共有で式を追加、正方系のみ採用、X=1..10 × 各 100 件）。CSTR の 3 式連立（物質収支 ODE＋反応速度式＋アレニウスの式）を例示。説明文生成のみ LLM（Claude）、他はすべて規則ベースであることを明記（G9）。
4. ソース単位の層化分割: 6:2:2、候補 400 通りから 4 特徴量分布の L1 距離最小を選択、乱数 10 通り。

### 第 5 章 Experiments

設定 A（原型＋複数文献＋DAE、1,823 件）と設定 B（DAE のみ 1,000 件）。拡張除外の根拠＝拡張込みだと baseline が +0.101 水増しされ本手法の効果を約 0.07 過小評価する。比較 3 手法（baseline＝古典 IR／reranker-10S＝本手法／LLM 直接生成）。指標: Recall@K・MAP・Recall@20、DoF 停止用に完全一致率・集合 F1・閉包率。LLM 等価性判定プロトコル（claude-opus-4-8）。API 固定モデル ID による再現性。

### 第 6 章 Results and Discussion — 弧は「性能→機構→介入→自己停止」

1. 全体結果: 設定 A 0.521→0.743（+0.222）、設定 B 0.466→0.689（+0.223）。全設定で本手法＞古典 IR＞LLM 直接生成。LLM は coverage（0.34–0.57）と順位付けの乖離を考察。
2. 特性別分析: 数式数・入力変数数が増えるほど優位が拡大（+0.03→+0.29）。ソース数は数式数と交絡。
3. 機構の実証: 特徴量×難易度クロス分析＝構造的集合特徴量（補完性・一貫性）が上乗せを担い、ドメイン一致の寄与はゼロ（p=0.98）。形は閾値＋こぶ、最難端で飽和。+0.22 の大半は MLP の 7 特徴量学習で、集合特徴量の純上乗せは +0.05。
4. 介入による因果確認: 学習版 greedy が飽和を回復（DAE 10 シードで静的 0.724 ＜ 推論 greedy 0.756 ＜ 学習版 0.765、X≥8 で +0.056）。「飽和を予測→介入→回復」の因果ストーリー。有意性の主張は §7 の検定実施後のみ（G2）。
5. DoF 停止: 完全一致率は K 既知の oracle と同一（DAE 0.368／A 0.526）、閉包率 0.88／0.94 ＞ oracle 0.78／0.87、集合 F1 コストは僅少（A −0.008）。K≒出力変数数という本データの限界も明記する。
6. 留意点: DAE 説明文が LLM 生成、ソース数の交絡、層化分割方式は 400 候補から選んだ 1 つ、DB 内評価であること。
