- **分割の書き方（§2 の「書き方の決まり」の訂正）**：「同じ出典が訓練用とテスト用にまたがらない（no source spans training and testing）」は、正解式については成り立たないので書かない。正しくは「各ケースを、正解式を最も多く出している出典に割り当て、出典ごとに分ける。同じ出典に割り当てたケースは同じ側に入る」。複数の出典の式から成る正解集合は、訓練用のケースと正解式を共有しうる。設定 A では、テスト用のケース延べ 4,229 件のうち 37.1%（分割ごとに 29.1〜43.5%。出典横断 69.9%、合成 17.3%、単一出典 4.7%）が、正解式を 1 本以上、訓練用のケースと共有する。設定 B では 8.4%（`experiments/llm_db_baseline/split_overlap.json`）。論文の 5.4 節と限界、修論に書いた。分割そのものは変えていない。

## 6. 数値の入れ方

- `paper/cace/make_numbers.py` が結果の JSON を読み、`numbers.tex` に `\newcommand` のマクロを書き出す（例 `\RecAProp` → 0.981）。本文と表はマクロだけを使う。
- 読む JSON: `experiments/kato1021/{main,mech,pfi,greedy,baselines,topic_diag_final,case_outcomes_final,data_counts,n1_coverage_w30-70,selected}.json`、`experiments/llm_db_baseline/{id_summary,opus_vs_proposed}.json`、`results_claude-{opus,haiku}-5-5__eqd__ex-none__high__v4.json`（quality、variability）。
- 丸めは 1 か所で決める（指標は小数 3 桁、割合は % で 1 桁、金額は 2 桁）。差は、丸める前の値の差を丸める（修論と同じ）。「−0.000」を出さない。
- 単体テスト（`tests/test_paper_numbers.py`）：丸め、符号つきの差、マクロの名前の重なりがないこと、既知の値（0.981 など）が出ること。
- JSON にない値（例：36 件のうち 28 件）は、計算するコードを `make_numbers.py` か分析のスクリプトに足し、JSON に保存してから使う。

4. **投稿規定の確認**（§4 の未確認の項目）。

7. **記号を付け替えた実験の扱い。** 2026-10-08 の報告の実験（前の設定：1,823 件、候補 50 件、R-Precision）では、クエリの記号の半分を別の記号に変えると、記号で照合する手法は 0.780 から 0.215 に下がった。修論は今「別の記法のクエリでの精度は未検証（remains untested）」と書いていて、この実験と合わない。選べるのは、(a) 限界に 1 文書く（前の設定での予備的な実験と断る。書き手の案）、(b) 今の設定でやり直して付録に載せる（API の費用なし、計算だけ）、(c) 書かない（その場合も「未検証」とは書かず、「本論文の実験では評価していない」と書く）。
