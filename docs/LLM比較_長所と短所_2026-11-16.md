## 2. Opus 5.5 が提案手法を上回ったケースの特徴

ケースごとに、Opus 5.5（3 回の平均）と提案手法（そのケースがテストに入る分割の平均）を比べた（設定 A の異なるテストケース 1,586 件）。

- **件数**：Recall@20 で Opus 5.5 が上回ったのは 36 件（2.3%）、同じが 1,064 件、下回ったのが 486 件。MAP@20 では上回ったのが 274 件、同じが 469 件、下回ったのが 843 件。
- **どこで**：Recall@20 で上回った 36 件はすべて合成のケースで、うち 26 件は正解式が 7 本以上。
- **正解式の写し（論文に書く 1 文）**：36 件のうち 28 件では、正解式と同じ式が別の ID でデータベースにあり、両方の手法の上位 20 件に入っていた（1 リストあたり平均 3.3 本）。ID の判定ではこれらは不正解になる。
- **提案手法の上位 20 件の中身**：提案手法は、変数がすべて入出力変数に含まれる式（同じ収支の別の形など）で上位 20 件を埋めやすい。正解式が 7 本以上の合成のケースで、正解でない式のうち変数がすべて入出力に含まれるものは、Opus 5.5 が上回ったケースで 1 リストあたり 9.2 本（Opus 5.5 は 4.1 本）。上回らなかったケースでも 8.1〜8.6 本で、提案手法に共通の誤り方である。
- **Opus 5.5 だけが拾った正解式**（36 件の中の 58 本）：入出力変数との変数の重複率（Jaccard 0.17、両方が拾った式は 0.22）も、説明文との文章の近さ（0.07、両方は 0.10）も低く、第 1 段の順位が深い（中央値 50.5 位、両方は 17 位）。変数も少ない（5.4 個、両方は 7.0 個）。例は、混合槽の定常の物質収支 0 = w₁x₁ + w₂x₂ − wx、エンタルピーの定義 Ĥ = C(T − T_ref)。
- **出典横断のケースの MAP@20**：正解式のうち変数の重複率が最も小さい式の Jaccard で 3 等分すると、提案手法の MAP@20 は重複率が大きい 2 群の 0.92 から小さい群の 0.86 に下がるが、Opus 5.5 は 0.77〜0.78 でほぼ一定。Opus 5.5 が上回ったケースの割合は、小さい群で 19.5%、ほかの 2 群で 8% と 6%。
- **上位 1 位**：MAP@20 で Opus 5.5 が上回ったケースでは、Opus 5.5 の 1 位は約 9 割が正解式（出典横断 0.90、合成 0.91）。提案手法の 1 位が正解式なのは出典横断で 0.58、合成で 0.73。

## 3. 長所と短所、用途の違い

### 提案手法

- **長所**
  - 精度：Recall@20 と MAP@20 が全体で最も高く、10 通りすべてで LLM を上回る。差は出典横断と合成のケース（複数の文献の式、多くの式から成るモデル）で大きい。
  - 入出力変数と式の変数記号の重複率を使うので、式の多いモデルでも必要な式を集めやすい。
  - 同じ入力に同じ順位を返す（回によって答えが変わらない）。1 ケースを解くのに API の料金がかからず、学習は 1 通りの分割につき 50〜100 秒。
  - データベースの大きさに入力の上限がない。LLM には渡せない変数記号の一覧と式周辺の文章も使える。
- **短所**
  - 正解の分かっている訓練用と検証用のケースが要る。
  - 変数の重複率に頼るので、変数がすべて入出力に含まれる別の形の式で上位を埋め、変数の重複率も文章の近さも低い正解式（定義式、定常の形など）を上位 20 件から押し出す。

### LLM（Claude Opus 5.5）

- **長所**
  - 例を見せずに（ゼロショット）解けるので、訓練用のケースが要らない。
  - 1 つの文献から作ったケースでは提案手法に近い（Recall@20 0.964 と 1.000）。
  - 変数の重複率も文章の近さも低い正解式を拾える。出典横断のケースでは、上位の精度（MAP@20）が変数の重複率にほとんど左右されない。上回ったケースでは 1 位の約 9 割が正解式。
  - baseline（古典的な情報検索）を 10 通りすべてで上回る。
- **短所**
  - 全体の精度は提案手法より低く、複数の文献の式や多くの式から成るモデルで差が開く。
  - 費用：Opus 5.5 の 5,019 回で 1,058.93 ドル。その 90.2% は呼び出しのたびにデータベースを読み出す料金で、データベースと問い合わせの数に比例して増える。
  - 入力の上限：データベースだけで 952,144 トークン（上限 100 万）で、変数記号の一覧と式周辺の文章は渡せない。データベースがこれより大きくなると、そのままでは渡せない。
  - 回によって答えが変わる：Recall@20 の回の間の標準偏差は 0.042、3 回とも同じ並びのケースは 0.06%、答えの集合の Jaccard 係数は 0.573。
  - モデルの規模に強く左右される：Haiku 5.5 は 0.497 で baseline を下回り、安全機能で 2.9% の呼び出しの答えが得られなかった。Opus 5.5 でも、指示どおり 20 個の ID を答えなかった回が 3.6% ある。

### 用途の違い（Discussion の案）

- 提案手法：大きなデータベースから、複数の文献の式や多くの式から成るモデルの式を、繰り返し安い費用で探すとき。正解の分かっているケースを用意できるとき。
- LLM：訓練用のケースがなく、1 つの文献にあるような小さなモデルの式を探すとき。提案手法が押し出しやすい、変数の重複率の低い式（定義式や定常の形）を拾う補助としても使える。
- 2 つを組み合わせる案（提案手法の候補を LLM に並べ直させる、など）は今後の課題。Opus 5.5 だけが拾った正解式が 58 本あることがその根拠になる。
