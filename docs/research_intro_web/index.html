01 ／ 物理モデルとは

「いい感じ」では工場は回らない

あなたが反応器を持つ工場のオーナーだと想像してください。スタッフに「この液体を入れたら何が出るか」と聞いたら、こう返ってきます ──

図 1：工場オーナーが欲しいのは「いい感じ」ではなく 計算できる数式の集まり（= 物理モデル）

加納研では、こうした場面で必ず「数式をください、数値をください」と問われます。定量的に記述できなければ、プロセスを管理することも改善することもできないからです。

物理モデルとは、あるプロセスの挙動を説明する 数式の集まり。
「何を入れると、何度の・どんな性質の・どれだけの製品が出るか」を計算可能にする。
02 ／ なぜ自動化が必要か

専門家にお願いすると、時間がかかりすぎる

物理モデル構築の現状は、専門家が論文と教科書を読み漁り、必要な式を手で拾い集めるプロセス。工場はその間ずっと止まっています。

図 2：物理モデル構築の所要時間 — 数週間 → 数時間 へ短縮が目標
出発点：この中間過程を AI で代替できれば、工場を動かしながらモデルを進化させられる。
03 ／ 先行研究

物理モデル自動構築の 3 流派

近年さかんに研究されているこの問題を、大きく 3 つの方針で整理できます。

図 3：3 流派の比較 — 我々は 「生成」ではなく「検索と選択」 に問題を変換する
我々の立ち位置：新しい数式を作るのではなく、人類がすでに書いた数式の中から、正しい組合せを選ぶ。
04 ／ 道具の選択

選ぶだけなら LLM でいい？ ── なぜ GNN なのか

LLM にカタログを渡して選ばせる手もありそうですが、LLM が扱えるのは 「平らに並んだ文字列」 だけ。数式データの持つ構造情報を活かせません。

図 4：LLM は式を 平文リストとして扱う／GNN は式と式の 関係性をグラフ構造として読む

式データにある関係性 ── 共通の変数を持つ、同じ分野で一緒に使われる、一方を解くために他方が必要 ── は、GNN にとって直接扱える情報源です。

GNN の強み：ノード（個体の属性）＋エッジ（つながり）を同時に読み、間接的な関係まで含めて個体の性質を補強する。
05 ／ 仕組みの直感 (1/3)

SNS の例え：A と C は友達かも？

A さんと C さんに直接の接点はない。でも共通の友達 Bがいる。
→ 「A と C も友達である可能性が高い」と推測できる。これが GNN の得意技です。

図 5：直接見えない関係を 共通ノードを介して推測 ── SNS も数式も同じ構造
数式データへの対応：
ノード = 数式 1 つ 1 つ　／　エッジ = 共通変数を持つ／同じ分野で一緒に使われる
06 ／ 仕組みの直感 (2/3)

映画の例え：キャスト 1 人でなく、チームを選ぶ

ラブコメ映画を作るとき、監督・男優・女優・エディターが必要。全員がバラバラでは良い作品にならない ── これと同じことが物理モデルにも言えます。

図 6：映画制作では 「役職」だけでなく「相性」 がチームの成否を決める。物理モデルの選択も同じ。
01

役職で選ぶ（個人の属性）

履歴書を見て条件に合う候補を拾う。監督候補、男優候補、女優候補…

→ 物理モデルでは：必要な入出力変数を含む・ドメインが合う式を候補にする
02

相性で選ぶ（チームの組合せ）

優秀な人を集めても連携しないとダメ。共演歴、作風の相性、ジャンル経験を見る。

→ 物理モデルでは：変数の共有関係・ドメイン一致 を「相性」として評価
07 ／ 仕組みの直感 (3/3)

最近の発見 ── ちょっとした失敗談

研究を進める中でハマった落とし穴。GNN の本領が発揮される場面を、このエピソードが教えてくれました。

図 7：「個人の優秀さ」だけで選ぶと 複数式タスクで失敗。
「組合せの相性」を加えると、正しい式の 仲間の集合を丸ごと 選べるようになった。
GNN の真価は「1 つ選ぶ」ではなく、
「正しい仲間の集合を選ぶ」問題で発揮される

01 ／ 問題

物理モデルが欲しい

プロセスの挙動を表す数式群を、専門家なしで作りたい

02 ／ 先行研究の限界

SR と LLM、両方に壁

SR は実験データが要る。LLM 直接生成はハルシネーション・再現性の問題

03 ／ 我々の立ち位置

「生成」から「選択」へ

文献の既知数式から選ぶ問題に変換 ─ ハルシネーションゼロ、根拠あり

04 ／ 道具の選択

GNN が最適

数式データには構造的関係（共有変数・共起）が豊富 → GNN の得意分野

05 ／ 最大のポイント

1 つより仲間の集合

GNN の真価は「1 つ選ぶ」ではなく「正しい組合せを選ぶ」問題で発揮

06 ／ 直感的な仕組み

ドメイン → 変数 → 相性
