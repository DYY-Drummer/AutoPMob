\begin{abstract}
本研究の目的は、複数の情報源から収集した数式の中から、作りたいモデルに使える可能性の高い数式を提示する手法を開発することである。提案手法は 2 段階の処理から構成される。第 1 段では、数式を、作りたいモデルの説明文と式周辺の文章の近さと、入出力変数の重複率で採点し、上位 $N_1$ 件に絞る。第 2 段では、10 個の特徴量を持つ多層パーセプトロンで並べ直し、上位 20 件を提示する。提案手法を 11{,}146 式と 1{,}731 ケースで評価した結果、上位 20 件に入った正解式の割合は、古典的な情報検索手法の 0.906 から 0.981 に上がった。本報告では、大規模言語モデルに全数式を渡して式を選ばせる比較の方法と、その費用を示す。費用の 69〜95\% は、呼び出しのたびに全数式を読み出す料金である。
\end{abstract}

\section{進捗と議論のポイント}
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{比較の目的}：同じデータベースと同じ判定の規則のもとで、提案手法と大規模言語モデル（large language model, LLM）のそれぞれの長所と短所を見つける。精度を比べるだけでなく、どのようなケースでどちらが正解式を上位に選べるか、費用、答えの回ごとのばらつきも比べる。高性能と低コストの 2 つのモデルを使い、モデルの規模による違いも見る。
  \item LLM との比較の方法を決め、実行の準備を済ませた。LLM に、データベースの全 11{,}146 式と、テストケース 1 件のクエリ（作りたいモデルの説明文と入出力変数）を渡して式を 20 個選ばせ、選んだ式が正解式かを、提案手法と同じく式の ID で判定する。
  \item テストケース 1{,}673 件を 2 つのモデルで 3 回ずつ解かせる費用を見積もった（モデルの組み合わせによって 1{,}421〜2{,}310 ドル）。有料のため、まだ実行していない。
  \item \textbf{議論したい点}：次の 2 点について、意見をいただきたい。
  \begin{enumerate}[label=(\arabic*), leftmargin=2em]
    \item この比較方法は公平か。この方法で、提案手法と LLM の性能を本当に比べられるか。
    \item 費用の 69〜95\% は、呼び出しのたびにデータベース（952{,}144 トークン。トークンは LLM が文字列を数える単位）を読み出す料金である。もっと費用を抑えて比べる方法はないか。
  \end{enumerate}
\end{itemize}


\section{大規模言語モデルとの比較の方法}\label{sec:method}
\subsection{何を比べるか}
LLM は多くの文献を学習しており、データベースを渡せば、作りたいモデルに使う式を自ら選べる可能性がある。そこで、LLM にも提案手法と同じデータベースとクエリを渡して式を選ばせ、提案手法と同じ規則で判定して、提案手法と古典的な情報検索手法（以下 baseline）と比べる。評価用の各ケースには、クエリと、作りたいモデルを構成する式の集合（正解集合。その式を正解式とよぶ）を決めてある。ケースは出典の単位で訓練用、検証用、テスト用に分け、分け方を 10 通り変えて評価する。これまでの比較では、LLM に式を書かせ、書かれた式が正解式と同じかを別の LLM に判定させていた。そのため、LLM と提案手法は別の問題を解いており、判定の方法も違っていた。10 月 14 日に加藤先生と議論し、データベースから式を選ばせて式の ID で判定する方法に改めた。

\subsection{LLM に渡すもの}
1 回の呼び出しで、LLM に、指示文、データベース、テストケース 1 件のクエリを渡す（指示文と入力の形は Appendix~A）。各手法が使う情報を Table~\ref{tab:inputs} にまとめる。
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{データベース}：各式を、ID、式の表記、分野ラベル（式が扱う分野の名前）の 3 つだけで渡す。使う LLM の入力の上限は 100 万トークンであり、この形でも、指示文とデータベースで 952{,}144 トークンになる。変数記号とその定義を加えると約 199 万トークンになって上限を超えるため、変数記号の一覧と定義、式周辺の文章は渡さない。ただし、式の表記には変数が記号で書かれている。
  \item \textbf{出典}：渡さない。式の並びを無作為にし、ID も 1〜11{,}146 の番号に振り直す（元の ID は出典の名前を含む）。提案手法は出典を使わないためである。また、合成のケース（微分方程式から始め、プログラムで式を足して作った 1{,}000 件）の正解集合は、同じ出典の式を優先して作ったので、出典が分かると、LLM だけが答えの手がかりを持つことになる。
  \item \textbf{解いた例}：渡さない。正解の分かっているケースを例として見せずに解かせる（ゼロショット）ためである。
  \item \textbf{答え方}：作りたいモデルに使う式の ID を、可能性の高い順に 20 個答えさせる。モデルを構成すると判断した式を先に挙げるよう指示する。指示文には、モデルの式の組が満たす条件として、\citet{CombineEq} の要件のうち変数と式の数え方に関する 3 つ（入出力変数がすべていずれかの式に現れる、式の数が入力変数以外の変数の数に等しい、入出力変数以外の変数は 2 本以上の式に現れる）を書く。
  \item \textbf{モデル}：Anthropic の LLM（Claude）から、高性能のもの（Claude Fable 5.1。費用が高ければ Claude Opus 5.5）と、低コストのもの（Claude Haiku 5.5 か Claude Sonnet 5.5）を 1 つずつ使う。答える前に考える量の設定（effort）は、どちらのモデルも high にそろえる。呼び出しはプログラムから行ない、モデル名、指示文の版、設定、日時、使ったトークン数、応答をすべて記録する。
\end{itemize}

\subsection{判定と指標}
\textbf{判定}：手法が答えた式の ID が正解集合 $R_q$（$q$ はクエリ）に含まれれば正解、含まれなければ不正解とする。データベースにない ID は不正解とし、その順位を占めるものとする。同じ ID が重なったときは、2 回目以降を除く。式どうしが等価かは判定しないので、正解式と同じ式が別の出典にあり、それを選んだ場合も不正解と数える。提案手法と baseline も同じ規則で判定する。ただし、LLM には出典も式周辺の文章も渡さないので、LLM は別の出典にある同じ表記の式を区別できない。そこで、空白と、\LaTeX{} の間隔や括弧の大きさの命令を除いて同じ文字列の式が別の出典にあれば、それも正解とみなした値もあわせて示す（どの手法にも同じ規則を当てる）。

\textbf{指標}：正解式の数を $K = |R_q|$、手法が並べた上位 20 件を $\Top_{20}(q)$ として、テスト用のケースごとに
\begin{equation*}
  \mathrm{Recall@20}(q) = \frac{|R_q \cap \Top_{20}(q)|}{K}, \qquad
  \mathrm{AP@20}(q) = \frac{1}{K} \sum_{e \in R_q} P(e)
\end{equation*}
を求める。$P(e)$ は、正解式 $e$ が上位 20 件にあれば、$e$ の順位までの式のうち正解式の割合、なければ 0 である。AP@20 のケースの平均を MAP@20（mean average precision）とよぶ。MAP@20 は、正解式がどれだけ上位に集まっているかを表す。LLM には 20 件を答えさせるので、どの手法も上位 20 件で比べる。

\textbf{比べ方}：提案手法と baseline と同じ 10 通りの分け方を使い、分け方ごとにテスト用のケースで平均した値を求めて、10 通りの平均 $\pm$ 標準偏差と、10 通りのうち何通りで一方が上回ったかを示す。評価は、全ケースを使う場合と、合成のケースだけを使う場合（分け方はそれぞれ 10 通り）の 2 つで行なう。比べる相手の値を Table~\ref{tab:reference} に示す。

\textbf{呼び出しの回数}：LLM には解いた例を渡さないので、同じケースへの入力は、どの分け方でも同じになる。そこで、異なるテスト用のケースごとに 3 回、独立に解かせ、その答えを、そのケースがテスト用に入るすべての分け方で使う。ケースの値は 3 回の平均とする。10 通りの分け方のテスト用のケースは、全ケースの評価で延べ 4{,}229 件、合成のケースの評価で延べ 2{,}432 件あり、異なるケースは合わせて 1{,}673 件である。したがって、呼び出しは 1 モデルにつき 5{,}019 回（1{,}673 件 $\times$ 3 回）である。Claude Haiku 5.5 で、種類の違う 3 件を 3 回ずつ解かせて試したところ、正解式が 5 本の合成のケースでは、Recall@20 が回によって 0.600、0.800、0.000 と変わった。そこで、回の間のばらつき（答えの一致と、Recall@20 の回の間の標準偏差）もあわせて示し、ばらつきが大きければ回数を増やし、小さければ減らす。

\subsection{費用}\label{sec:cost}
1 回の入力は、指示文とデータベースの 952{,}144 トークンと、テストケースの平均 354 トークンである。データベースの部分は毎回同じなので、プロンプトキャッシュを使う。プロンプトキャッシュは、入力の先頭部分を保存しておき、次の呼び出しでは、その部分を通常の入力の 2.5〜10\%（モデルによる）の料金で読み出す仕組みである（保存には、通常の入力の 1.25 倍の料金がかかる）。出力のトークン数（答える前に考えた分を含む）は、Claude Haiku 5.5 では、3 件を 3 回ずつ解かせた試しの実測から 1 回約 970 トークンとし、ほかのモデルでは 1 回 2{,}000 トークンと仮定した。料金は、2026 年 11 月 1 日に確かめた料金表~\citep{AnthropicPricing}による。

見積もりを Table~\ref{tab:cost} に示す。1 モデルで 5{,}019 回を流す費用は 253〜1{,}726 ドルで、2 モデルでは、組み合わせによって 1{,}421〜2{,}310 ドルになる。どのモデルでも、費用の 69〜95\% は、呼び出しのたびにデータベースを読み出す料金である。出力が 1 回 70〜8{,}000 トークンの範囲で変わると、合計は Table~\ref{tab:cost} の右端の列のように変わる。

\section{LLM に与える指示文と入力の形}\label{app:prompt}
system として指示文を、user の 1 つ目のブロックとしてデータベースを、2 つ目のブロックとしてテストケースを、この順に送る。データベースのブロックの末尾にキャッシュの区切りを置くので、2 回目以降の呼び出しでは、指示文とデータベースをキャッシュから読み出す。どのモデルにも同じ指示文を使う。\texttt{<TAB>} はタブ文字を表す。データベースは、11{,}146 行のうち先頭の 1 行だけを示す。テストケースの \texttt{< >} の部分には、そのケースの説明文と変数記号を入れる。
\begin{Verbatim}[fontsize=\scriptsize, breaklines=true, frame=single]
[system]
You are an expert in physical modeling. You select equations from an equation database for building a physical model.

# Task
An engineer wants to build a physical model: a set of equations with which the output variables can be computed once the input variables are given. The engineer describes the model and lists its input variables and output variables. Choose, from the equation database, the equations that the engineer should use.

The set of equations that forms the model satisfies these conditions:
1. Every input variable and every output variable appears in at least one equation of the set.
2. The number of equations equals the number of variables of the set that are not input variables.
3. Every variable of the set that is neither an input nor an output variable appears in at least two equations of the set.

# Equation database
<equation_database> lists equations extracted from the literature, in no particular order. Each line has three fields separated by tabs: the equation ID, the domain label of the equation, and the equation in LaTeX.

# Answer
For the task in <task>, list 20 equation IDs, from the most to the least likely to belong to the model. Put first the equations that you judge to form the model. Use only IDs from the database, and list each ID once. In the task, variable symbols in a list are separated by " ; ".

[user, block 1: equation database, cached]
<equation_database count="11146">
1<TAB>Educational Psychology Time-Series Analysis<TAB>MSSD = \frac{1}{N-1} \sum_{t=2}^{N} (x_t - x_{t-1})^2
...
</equation_database>

[user, block 2: test case]
<task>
Description: <description of the model>
Input variables: <symbol> ; <symbol> ; ...
Output variables: <symbol> ; ...
</task>

List the IDs of the database equations for this task.

[output format (JSON schema)]
{"type": "object", "properties": {"equation_ids": {"type": "array", "items": {"type": "integer"}}}, "required": ["equation_ids"], "additionalProperties": false}
\end{Verbatim}
