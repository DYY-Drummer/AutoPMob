\section{本報告の位置づけ}
%======================================================================
本研究の目的は、複数の情報源から収集した数式の中から、作りたいモデルに使える可能性の高い数式を提示する手法を開発することである。提示した数式からモデルを組み立てて確かめるのは利用者である。

本報告は、問題設定と提案手法（\S\ref{sec:method}）、実験方法（\S\ref{sec:data}）、結果と考察（\S\ref{sec:overall}〜\S\ref{sec:error}）、現時点の限界（\S\ref{sec:limits}）をまとめたものである。10 月 12 日版に頂いたコメントと、10 月 14 日の議論を受けて、次の点を改めた。
\begin{enumerate}[label=(\arabic*), leftmargin=2.2em]
  \item 第 1 段の検索で残す候補の件数を、正解式がすべて候補に入る件数にし、すべての実験でそろえた。
  \item 提示する式の数を 20 件に固定し、主な指標を Recall@20 にした。提示する式の数を決める規則（自由度ゼロ停止）はやめた。
  \item 入力変数を与えても一部の未知の変数が決まらない 91 件と、2 冊の教科書の式から成る単一出典の 1 件を、評価からも訓練からも除いた。
  \item 手法のハイパーパラメータ（訓練の前に決めておく値）のうち、比較手法と提案手法の重みと、訓練に使う不正解の選び方を、検証用のケースで選ぶようにした。
  \item LLM との比較を、データベースを LLM に渡し、選んだ式を ID で判定する形に改めることにした（結果は次の版で示す）。
  \item 検定をやめ、10 通りの分割のうち何通りで一方の手法が上回ったかを示した。
  \item データベースと評価ケースの作り方を、生成したプログラムと実データで確かめて書き直した。10 月 12 日版にあった誤り（拡張ケースの使い方、式の抽出に使った LLM、出典横断のケースの作り方の記述）を直し、文献の一覧と、LLM に与えたプロンプトを付録に加えた。
\end{enumerate}

なお、出典横断のケース 113 件の説明文を入出力変数に合うように書き直し、単一出典の 1 件を除いたので（\S\ref{sec:cases}）、実験をやり直している。\S\ref{sec:compared} 以降と付録 A〜C の具体的な数値は、この追加実験の計算が終わったら更新する（今の数値は、書き直す前のケース 1{,}732 件での結果である）。

\subsection{問題設定}\label{sec:problem}
作りたい物理モデルとは、値が分かっている変数（入力変数）から、求めたい変数（出力変数）を計算できる式の組である。\citet{CombineEq} は、文献から抽出した式を組み合わせてこのようなモデルを作る問題を定式化し、作りたいモデルの式の集合 $S$ が満たすべき条件として、次の 4 つの要件を定めた。ここで $V(S)$ は $S$ の式に現れる変数の集合、$\Vin$ と $\Vout$ は入力変数と出力変数の集合である。
\begin{enumerate}[leftmargin=2.2em]
  \item 入出力変数の包含：入出力変数がすべて $S$ の式に現れる（$\Vin \cup \Vout \subseteq V(S)$）。
  \item 自由度の整合：$S$ の自由度 $\Ndof(S) = |V(S)| - |S|$（変数の数と式の数の差。\citealp{Seborg}）が、入力変数の数に等しい（$\Ndof(S) = |\Vin|$）。要件 1 のもとでは、入力変数の値を与えたときに残る未知の変数の数 $|V(S) \setminus \Vin|$ が、式の数 $|S|$ に等しいことと同じである。
  \item 可解性：入出力変数以外の変数は、$S$ の 2 本以上の式に現れる。
  \item 定数の一意性：定数を表す変数は、1 本の式（変数 $=$ 定数）だけで定義される。
\end{enumerate}
これらは必要条件であり、満たした式の組がモデルとして役に立つとは限らない~\citep{CombineEq}。

\citet{CombineEq} は、与えられた式の集合から、要件を満たす組合せをすべて求める。本研究は、多数の文献から作った大規模な数式データベースの中から、\citet{CombineEq} の手法に必要な式、つまり作りたいモデルを組むのに必要な式を選ぶ問題を扱う。提案手法は、\citet{CombineEq} の手法の上流に置くことができ、膨大な数の数式から有用な数式を見つけるときにも使える。

入力はクエリ（検索の入力として与える文や語）$q = (c, \Vin, \Vout)$ であり、$c$ は作りたいモデルを自然言語で説明した文（説明文）、$\Vin$ と $\Vout$ は入力変数と出力変数の記号の集合である。$V_q = \Vin \cup \Vout$ を入出力変数とよぶ。数式データベース $E = \{e_1, \dots, e_N\}$ の各式 $e$ は、次の 5 つの情報を持つ（作り方は \S\ref{sec:db}）。
\begin{itemize}[leftmargin=1.5em]
  \item 式の表記：\LaTeX{} 形式の式。
  \item 変数の集合 $V(e)$：式に現れる変数記号の集合。各記号には、文献に書かれた定義の文章が付く。
  \item 式周辺の文章：式を抽出するときに LLM が、式の前後の本文をもとに書き出した、その式の物理的な意味を説明する文章。
  \item 出典：式を抽出した文献の名前。
  \item 分野ラベル $d(e)$：式が扱う分野やプロセスの名前（例：CSTR）。式を抽出するときに LLM が自由に書いた文字列であり、決まった分類から選んだものではない。
\end{itemize}
変数どうしは、記号の文字列が完全に一致するときだけ同じ変数とみなす。この照合は、クエリの変数と式の変数を比べるときも、式どうしの変数を比べるときも同じであり、表記の統一はしない（$C_A$ と $C_A(t)$ は別の変数として扱う）。変数記号に付いた定義の文章は使わない。そのため、記号が同じなら、定義の文章が違っても同じ変数とみなす（データベースでの数と例は \S\ref{sec:db}）。

手法の出力は、データベースの式の順位である。提案手法は、作りたいモデルに必要な可能性の高い式ほど上位に並べ、上位 $n$ 件を提示する（本報告では $n = 20$）。

手法を評価するため、評価に使うケースには、クエリとともに、作りたいモデルを構成する式の集合 $R_q \subset E$ を 1 つ定めてある（\textbf{正解集合}。作り方は \S\ref{sec:cases}）。$R_q$ に含まれる式を\textbf{正解式}、それ以外の式を\textbf{不正解式}とよび、$K = |R_q|$ を正解式の数とする。評価に使う 1{,}731 ケースの正解集合は、すべて要件 1〜3 を満たす。要件 1〜3 は変数と式の数え方の条件であり、未知の変数のそれぞれに、それを決める式を 1 本ずつ割り当てられるかは見ない。そこでこの割り当ても確かめ、割り当てのできない 91 件を評価から除いた（\S\ref{sec:cases}）。要件 4 は、どの変数が定数を表すかをデータベースが区別していないため、確かめていない。また、1{,}724 件では入出力変数以外の変数がないので、要件 3 は自明に満たされる。式は ID（出典と出典内の番号の組）で区別するので、正解式と同じ式が別の出典にあり、それを選んだ場合は不正解と数える（同じ式を正解とみなした場合の結果も \S\ref{sec:overall} に示す）。

\subsection{提案手法の概要}\label{sec:overview}
提案手法は、2 段階の検索でデータベースの式を並べ替える（図~\ref{fig:overview}）。
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{第 1 段の検索（候補の絞り込み）}：データベースの全 $N$ 式に、クエリとの関連の強さを表す簡単な点数を付け、上位 $N_1$ 件を候補として残す。
  \item \textbf{第 2 段の検索（候補の並べ直し）}：候補 $N_1$ 件のそれぞれについて 10 個の特徴量を計算し、多層パーセプトロン（multilayer perceptron, MLP）が特徴量から候補の点数を計算する。候補を点数の高い順に並べ直す。10 個のうち 3 個は、候補をほかの式の集合（\textbf{参照集合}）と比べる特徴量である。物理モデルでは、ある式に現れる変数をほかの式が決めるので、ある式が使えるかどうかは、一緒に提示する式によって変わる。この 3 個はそれを点数に反映させる。
\end{itemize}
第 2 段の並べ直し方には 2 通りある。基本形の\textbf{一括の並べ直し}は、参照集合を第 1 段の上位 $m$ 件に固定し、全候補を 1 回で点数化する（\S\ref{sec:stage2}）。拡張形の\textbf{逐次選択}は、式を 1 本ずつ選び、選ぶたびに、それまでに選んだ式を参照集合にして点数を計算し直す（\S\ref{sec:seqmethod}）。提示するのは、並べた式の上位 $n$ 件である。手法のハイパーパラメータ（訓練の前に決めておく値で、訓練で決まる MLP のパラメータとは別のもの。$N_1$、$m$、第 1 段の重み、$\gamma$、$n_{\mathrm{neg}}$、エポック数、学習率）の値は \S\ref{sec:compared} に示す。

\subsubsection{第 1 段の検索：候補の絞り込み}\label{sec:stage1}
第 1 段の検索は、データベースの各式 $e$ に対して、クエリ $q$ との点数
\begin{equation}
  s_1(q, e) = w_{\mathrm{t}} \cos\bigl(\phi(c), \phi(T(e))\bigr) + w_{\mathrm{v}} \, J\bigl(V_q, V(e)\bigr)
  \label{eq:stage1}
\end{equation}
を計算し、点数の高い上位 $N_1$ 件を候補 $C_q$ とする。第 1 項は説明文と式の文章の近さ（\textbf{文章類似度}）、第 2 項は入出力変数と式の変数の重なり（\textbf{変数の一致度}）であり、$w_{\mathrm{t}}$ と $w_{\mathrm{v}}$ はその重みである。$T(e)$ は、式 $e$ の式周辺の文章、式の表記、分野ラベルをつなげた文字列である。$\phi(\cdot)$ は文字列の TF-IDF（term frequency--inverse document frequency）ベクトルで、各単語に、その文字列での出現回数と、データベースの式の文字列全体での珍しさを掛けた重みを付ける。単語 1 語と、隣り合う 2 語の組を単位とし、語彙はデータベースの全式の $T(e)$ から作る。$\cos(\cdot, \cdot)$ は 2 つのベクトルのコサイン類似度、$J(A, B) = |A \cap B| / |A \cup B|$ は 2 つの集合の Jaccard 係数である。

第 2 段の検索は候補の中でしか並べ直せないので、正解式のうち候補に入った割合（\textbf{被覆率}、\S\ref{sec:eval}）が、第 2 段で得られる精度の上限になる。被覆率は、重み $(w_{\mathrm{t}}, w_{\mathrm{v}})$ と候補の件数 $N_1$ の両方で変わる。本報告では、$N_1$ を、正解式がすべて候補に入る大きさにする（\S\ref{sec:compared}）。

\subsubsection{第 2 段の検索：一括の並べ直し}\label{sec:stage2}
第 2 段の検索は、候補 $e \in C_q$ ごとに 10 個の特徴量を並べたベクトル $x(q, e)$ を作り、MLP $f$ で点数 $f(x(q, e))$ を計算して、候補を点数の高い順に並べ直す。表~\ref{tab:features} に 10 個の特徴量をまとめる。以下で各特徴量を定義する。

\textbf{基本の 7 個}は、クエリと候補 1 本を比べる。
\begin{itemize}[leftmargin=1.5em]
  \item $x_1$ 文章類似度：式~\eqref{eq:stage1} の第 1 項と同じ $\cos(\phi(c), \phi(T(e)))$。
  \item $x_2$ 変数の一致度：式~\eqref{eq:stage1} の第 2 項と同じ $J(V_q, V(e))$。
  \item $x_3$ 潜在意味類似度：データベースの全式の $T(e)$ の TF-IDF ベクトルに切断特異値分解（truncated singular value decomposition, SVD）を当てはめて 256 次元に縮約し（潜在意味解析（latent semantic analysis, LSA））、縮約した空間で、クエリと式 $e$ のコサイン類似度をとる。クエリ側の文字列には、説明文 $c$ に入出力変数の記号を付け加える。縮約した空間では、同じ文字列に一緒に現れやすい単語が同じ次元にまとまるので、同じ単語を含まなくても、似た文字列に現れる単語を含めば値が大きくなる。
  \item $x_4$ 入力変数の被覆率：$|\Vin \cap V(e)| / |\Vin|$。入力変数のうち式に現れる割合。
  \item $x_5$ 出力変数の被覆率：$|\Vout \cap V(e)| / |\Vout|$。出力変数のうち式に現れる割合。
  \item $x_6$ 式の特化度：$|V_q \cap V(e)| / |V(e)|$。式の変数のうち入出力変数が占める割合。入出力変数以外の変数を持たない式ほど 1 に近い。
  \item $x_7$ 分野ラベルの一致：分野ラベル $d(e)$ が説明文 $c$ に文字列として含まれるか、$c$ が $d(e)$ に含まれれば 1、そうでなければ 0（大文字と小文字は区別しない）。
\end{itemize}

\textbf{集合の 3 個}は、候補 $e$ を参照集合 $S$ と比べる。参照集合は、候補を評価するときに比べる相手とする式の集合であり、一括の並べ直しでは、第 1 段の検索の結果得られる上位 $m$ 件とする。候補自身が参照集合に入っているときは、その候補を除いた参照集合と比べる。$V(S)$ は $S$ の式に現れる変数の集合である。
\begin{itemize}[leftmargin=1.5em]
  \item $x_8$ 補完性：$|(V_q \cap V(e)) \setminus V(S)| / |V_q|$。入出力変数のうち、参照集合の式が持つ変数の集合には含まれないが、候補式が持つ変数の集合には含まれる変数の割合。
  \item $x_9$ 一貫性：$|V(e) \cap V(S)| / |V(e)|$。候補式の変数のうち、参照集合の式にも現れる変数の割合。
  \item $x_{10}$ 分野ラベルの一致度（集合）：$|\{e' \in S : d(e') = d(e)\}| / |S|$。参照集合の式のうち、分野ラベルが候補式の分野ラベルと文字列として完全に一致する式の割合。
\end{itemize}

MLP は、10 個の特徴量を入力とし、64 ユニットの隠れ層 2 層（活性化関数 ReLU、ドロップアウト率 0.1）を経て 1 つの点数を出力する。訓練では、正解式の点数が、同じケースの不正解の候補の点数よりマージン $\gamma$ 以上大きくなるように学習する。訓練ケース $q$ の正解式 $e^+ \in P_q = R_q \cap C_q$ と不正解の候補 $e^-$ の組ごとに
\begin{equation}
  \ell(q, e^+, e^-) = \max\bigl(0,\ \gamma - f(x(q, e^+)) + f(x(q, e^-))\bigr)
  \label{eq:loss}
\end{equation}
を計算する。$e^-$ は、不正解の候補 $C_q \setminus R_q$ から選んだ $n_{\mathrm{neg}}$ 件である。選び方は次の 2 通りを比べ、検証用のケースで良い方を使う（\S\ref{sec:compared}）。(a) 無作為に選ぶ。(b) 訓練のその時点の MLP の点数が高い順に選ぶ（hard negative）。候補の件数 $N_1$ が大きいと、無作為に選んだ不正解の候補の多くは、正解式との点数の差がすでにマージンを超えていて、損失に寄与しない。そのため (b) を加えた。訓練ケース 16 件ごとに、そこに含まれるすべての組の $\ell$ の平均を損失として、MLP のパラメータを更新する。正解式の点数が不正解の候補の点数を $\gamma$ 以上上回れば、その組の損失は 0 になる。

\subsubsection{第 2 段の拡張：逐次選択}\label{sec:seqmethod}
一括の並べ直しは、参照集合を第 1 段の上位 $m$ 件に固定する。正解式の数 $K$ が大きいケースでは、実際に上位に並ぶ式と、固定した参照集合が食い違っていく。逐次選択は、参照集合を「それまでに選んだ式」に置き換えて、式を 1 本ずつ選ぶ。推論の手順は次のとおりである。
\begin{enumerate}[leftmargin=2.2em]
  \item 1 本目には、一括の並べ直しの点数（固定の参照集合で計算した点数）が最も高い候補を選ぶ。
  \item 2 本目以降は、それまでに選んだ式の集合を参照集合として、残りの候補の $x_8$〜$x_{10}$ を計算し直し、点数が最も高い候補を選ぶ。
  \item 手順 2 を、$n$ 本選ぶか候補がなくなるまで繰り返す。選ばれなかった候補は、一括の並べ直しの点数の順に後ろへ並べる。
\end{enumerate}
逐次選択には、MLP の訓練方法の異なる 2 通りがある。\textbf{逐次選択（推論のみ）}は、一括の並べ直しと同じ方法で訓練した MLP を、上の手順で使う。\textbf{逐次選択（訓練も逐次）}は、訓練でも推論と同じ形の参照集合を使う。このとき参照集合には、MLP が自分で選んだ式ではなく、正解式を入れる。系列を 1 つずつ生成するモデルの訓練で、前の段階の出力の代わりに正解を与える方法（teacher forcing）と同じ考え方である。

各訓練ケースで、候補に入った正解式を第 1 段の検索の順位の順に $e^+_1, e^+_2, \dots$ と並べ、段階 $t = 1, 2, \dots$ ごとに損失を加える。段階 $t$ では、正解式 $e^+_1, \dots, e^+_{t-1}$ を「それまでに選んだ式」とみなして参照集合とし（$t = 1$ では第 1 段の上位 $m$ 件）、その参照集合で計算した特徴量について、次の正解式 $e^+_t$ と不正解の候補の組の損失 $\ell$（式~\eqref{eq:loss}）を加える。たとえば正解式が 3 本のケースでは、段階 1 では第 1 段の上位 $m$ 件を参照集合として $e^+_1$ を、段階 2 では $\{e^+_1\}$ を参照集合として $e^+_2$ を、段階 3 では $\{e^+_1, e^+_2\}$ を参照集合として $e^+_3$ を、不正解の候補より上に並べるように学ぶ。段階の数は 1 ケースあたり最大 8 である。こうすると、訓練でも推論と同じ問い（「これらの式を選んだ今、次に選ぶべき式はどれか」）を学ぶ。ただし、推論では自分が選んだ式（誤りを含みうる）を参照集合にするのに対し、訓練では正解式を参照集合にする点が異なる（\S\ref{sec:limits}）。

評価ケースは、クエリ（説明文と入出力変数）と正解集合の組である。正解集合の作り方が異なる 3 種類のケースを作り、入力変数を与えても一部の未知の変数が決まらない 91 件（\S\ref{sec:problem}）と、単一出典のうち 2 冊の教科書の式から成る 1 件を除いた 1{,}731 件を評価に使う（表~\ref{tab:cases}）。どの種類でも、入出力変数は正解式に現れる変数記号から選んでいる。

\textbf{単一出典}（91 件）：LLM（Gemini 2.5 Pro）に、データベースの式の一覧を渡してケースを作らせた（プロンプトは\ref{app:prompts}）。一覧には、式ごとに ID（出典名を含む）、分野ラベル、変数記号だけを載せ、式の表記と式周辺の文章は載せていない。当時のデータベース（3{,}244 式）を、分野ラベルの順に 300 式以下ずつ 11 回に分けて渡し、1 回に 13 件を作らせた。LLM には、一覧の式を組み合わせて、物理的に意味のあるケース（説明文、入力変数、出力変数、正解集合）を作るよう指示し、正解集合の条件として、入力変数の値から出力変数をすべて求められることと、必要十分かつ最小であること（余分な式を含まないこと）を課した。LLM が作った 123 件のうち、正解式がすべてデータベースにあり、入出力変数がすべて正解式に現れ、入力変数を与えたときの未知の変数の数と式の数が等しい 92 件を残した。したがって、92 件という数は出典の数（361 件）とは対応しない。92 件のうち 1 件は、正解集合が 2 冊の教科書（\citealp{Seborg} と Marlin の Process Control）の式から成っていた。一覧を出典ではなく分野ラベルの順に分けて渡し、出典を 1 つにする条件も課さなかったため、同じ回の一覧にあった 2 冊の式を LLM が組み合わせたものである。同じ作り方のケースはこの 1 件だけなので、評価にも訓練にも使わない。残る 91 件の正解集合は 1 つの出典の式だけから成るので、単一出典とよぶ。正解集合は、出典が 1 つのモデルとして示す式の組ではなく、LLM が最小と判断した組である（最小かどうかは確かめていない）。91 件中 67 件は 1 式、61 件は基礎式集の式だけから成る。

\subsection{訓練、検証、テストの分割}\label{sec:split}
訓練、検証、テストへの分割は、出典を単位として行なう。同じ出典の式を正解に含むケースが訓練とテストの両方に入ると、テストの正解を訓練で見たことになるためである。各ケースは、正解式の出典のうち最も多いものに属するとする。出典の一覧を無作為に並べ替え、出典の 20\% をテスト、20\% を検証、60\% を訓練に割り当てる。割合を決めているのは出典の数であり、出典ごとに属するケースの数は違うので、テスト、検証、訓練のケースの数は分割ごとに変わる（設定 A では、テストのケースが 298〜527 件、検証のケースが 216〜349 件）。検証用のケースは、ハイパーパラメータを選ぶのに使う（\S\ref{sec:compared}）。

この割り当てを 1 回だけ無作為に行なうと、正解式の数の多いケースが一方に偏ることがある。そこで、割り当てを 400 通り無作為に作り、その中から、訓練とテストでケースの分布が最もそろう 1 通りを選ぶ（\textbf{層化}）。分布をそろえる量は、ケースごとの正解式の数、入力変数の数、出力変数の数、正解式の出典の数の 4 つである。それぞれの量について、訓練とテストの度数分布を割合に直し、値ごとの割合の差の絶対値を足した L1 距離を求める。4 つの量の L1 距離の和が最小になる割り当てを選ぶ。

この分割を、乱数の種を 10 通り（42、123、456、789、1024、2024、3141、5926、7777、9999）に変えて繰り返す。乱数の種が変わると、400 通りの候補も、選ばれる分割も変わるので、10 通りの異なる分割で評価することになる。MLP の初期値と、不正解の候補の抽出も、同じ乱数の種で決まる。すべての手法を同じ 10 通りの分割で評価し、10 通りの平均と標準偏差を報告する。

\subsection{比較手法とハイパーパラメータ}\label{sec:compared}
比較手法は次の 2 つである。

\textbf{古典的情報検索手法（baseline）}：第 1 段の検索と同じ点数 $s_1$（式~\eqref{eq:stage1}）で、データベースの全式を並べる。学習も候補の絞り込みもしない。重み $(w_{\mathrm{t}}, w_{\mathrm{v}})$ は、$(1.0, 0.0)$ から $(0.0, 1.0)$ までの 12 通りを比べ、分割ごとに、検証用のケースの Recall@20（\S\ref{sec:eval}）が最も高い重みを選んで、テストのケースで評価する（選ばれた重みは、設定 A で $(0.4, 0.6)$ と $(0.3, 0.7)$ が 5 通りずつ、設定 B で $(0.3, 0.7)$ が 5 通り、$(0.2, 0.8)$ が 3 通り、$(0.4, 0.6)$ が 2 通り。12 通りの結果は\ref{app:weights}）。文章類似度を BM25~\citep{BM25} や E5（文の埋め込みベクトル）~\citep{E5} の類似度に置き換えた比較も\ref{app:weights} に示す。

\textbf{LLM}：LLM に、データベースの全式と、テストケース 1 件のクエリを渡し、作りたいモデルに使う式の ID を、可能性の高い順に最大 20 個返させる。解いたケースの例は与えない。データベースの各式は、ID、式の表記、分野ラベルだけで渡す。変数の定義と式周辺の文章まで含めると、LLM の入力の上限（100 万トークン）を超えるためである。出典は渡さず、式の並びを無作為にして ID も振り直す。提案手法は出典を使わず、合成のケースの正解集合は同じ出典の式を優先して作ったので、出典が分かると、LLM だけが答えの手がかりを持つことになるためである。モデルは、規模の異なる Claude Haiku 5.5、Claude Sonnet 5.5、Claude Opus 5.5、Claude Fable 5.1 の 4 つで、答える前に考える量の設定（effort）はすべて high とする（プロンプトは\ref{app:prompts}）。LLM は訓練のケースを見ないので、同じケースへの入力は分割によらない。そこで、各ケースを 1 回だけ解かせ、その答えを、そのケースがテストに入るすべての分割で使う。

\textbf{提案手法}：\S\ref{sec:overview} の手法である。第 1 段の重みは、$(0.7, 0.3)$、$(0.5, 0.5)$、$(0.3, 0.7)$、$(0.0, 1.0)$ の 4 通りを、検証用のケースの Recall@20 で比べた。重みによる差は、設定 A で 0.980〜0.983、設定 B で 0.974〜0.975 であり、分割の違いによるばらつき（標準偏差 約 0.015）より小さかった（\ref{app:weights}）。そこで、正解式がすべて候補に入る $N_1$ が最も小さい重み $(0.3, 0.7)$ を、すべての分割で使う。候補の件数 $N_1$ は、訓練と検証のケースで正解式がすべて候補に入る最小の件数を分割ごとに求め、千の位に切り上げた $2{,}000$ とする（重み $(0.3, 0.7)$ では、10 通りの分割のどれでも 2{,}000 になった。ほかの重みでは 2{,}000〜6{,}000 になる）。不正解の選び方（無作為と hard negative）は、分割ごとに、検証用のケースの Recall@20 が高い方を選んだ（20 通り中 19 通りで hard negative）。参照集合の大きさ $m = 5$、マージン $\gamma = 0.1$、不正解の抽出数 $n_{\mathrm{neg}} = 8$ とし、AdamW（学習率 $10^{-3}$、重み減衰 $10^{-4}$）で 15 エポック訓練する。これらの値は以前から使っているもので、ほかの値とは比べていない。

\subsection{評価方法}\label{sec:eval}
\textbf{正解の判定}：すべての手法は、データベースの式の ID を返す（LLM には、渡した式の ID で答えさせる）。返した ID が正解集合 $R_q$ に含まれるかで、正解かどうかを判定する。データベースにない ID は不正解とし、同じ ID が重なったときは 2 回目以降を除く。式の等価性は判定しない。ID による判定では、正解式と同じ式が別の出典にあり、それを選んだ場合も不正解と数える。正解式 3{,}132 本のうち 386 本（12.3\%）は、空白と、\LaTeX{} の間隔や括弧の大きさの命令を除いて同じ文字列の式が、別の出典にもある（\S\ref{sec:errtypes}）。そこで、このような式も正解とみなした場合の結果も示す（1 本の正解式について同じ式が複数並んでも、1 回だけ数える）。

\textbf{指標}：各ケースについて次の量を求め、テストのケースで平均した値を 1 つの分割の値とする。$\mathrm{Top}_n(q)$ は、手法が並べた上位 $n$ 件である。
\begin{itemize}[leftmargin=1.5em]
  \item Recall@20 $= |R_q \cap \mathrm{Top}_{20}(q)| / K$（主指標）：上位 20 件に、正解式がどれだけ含まれるか。
  \item MAP（mean average precision）：各ケースの平均適合率 $\mathrm{AP}(q) = \frac{1}{K} \sum_{e \in R_q} P(e)$ のケース平均。$P(e)$ は、正解式 $e$ の順位までの上位の式のうち正解式の割合である（$e$ が並べた中にないときは 0）。正解式がどれだけ上位に集まっているかを表す。LLM は 20 件しか返さないので、LLM との比較では、上位 20 件に入らない正解式の $P(e)$ を 0 とした MAP@20 を使う。
  \item R-Precision $= |R_q \cap \mathrm{Top}_K(q)| / K$：上位 $K$ 件（$K$ は正解式の数）に入った正解式の割合（10 月 12 日版の $\rk$）。
  \item 被覆率 $= |R_q \cap C_q| / K$：第 1 段の検索の候補に入った正解式の割合。
\end{itemize}

\textbf{手法の比べ方}：検定は行なわない。2 つの手法を比べるときは、10 通りの分割の平均の差と、10 通りのうち何通りで一方が上回ったかを示す。差は、丸める前の平均から計算した。

\section{結果 2：向上の内訳と、モデルが頼っている特徴量}\label{sec:mech}
%======================================================================
ここでは、第 2 段の検索が、同じ重み $(0.3, 0.7)$ の baseline から Recall@20 を $+0.074$、MAP を $+0.170$ 上げた内訳を調べる（設定 A）。以下の比較では、特徴量の組ごとに MLP を訓練し直し、同じ 10 通りの分割で評価した平均を示す。
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{(i) 重みの学習}：第 1 段の点数の 2 項（文章類似度 $x_1$ と変数の一致度 $x_2$）だけを特徴量として MLP を訓練すると、Recall@20 は 0.907 から 0.892 に、MAP は 0.690 から 0.680 に下がる（baseline を上回ったのは、10 通り中 4 通りと 3 通り）。2 つの値の重みを学び直しても、精度は上がらない。
  \item \textbf{(ii) 基本の特徴量}：2 個に残りの基本の特徴量 5 個（$x_3$〜$x_7$）を加えて 7 個にすると、Recall@20 は 0.892 から 0.975 に（$+0.083$）、MAP は 0.680 から 0.787 に（$+0.107$）上がる（どちらも 10 通りすべてで上回った）。5 個のうち式の特化度 $x_6$ だけを加えても、Recall@20 は 0.972（$+0.080$）、MAP は 0.786（$+0.106$）になり、この段階の向上はほとんど式の特化度による。
  \item \textbf{(iii) 集合の特徴量}：基本の 7 個に集合の 3 個（$x_8$〜$x_{10}$）を加えると、Recall@20 は 0.975 から 0.981 に（$+0.006$）、MAP は 0.787 から 0.860 に（$+0.073$）上がる（どちらも 10 通りすべて）。Recall@20 はすでに 0.975 で上がる余地が小さく、集合の特徴量は主に、上位 20 件の中での正解式の順位を上げる。
\end{itemize}
集合の 3 個を 1 個ずつ基本の 7 個に加えて訓練し直すと、MAP は、補完性 $x_8$ で $+0.073$、一貫性 $x_9$ で $+0.071$、分野ラベルの一致度（集合）$x_{10}$ で $+0.013$ 上がった（どれも 10 通りすべて）。3 個すべてを加えたときの $+0.073$ は、補完性か一貫性の 1 個を加えたときと同程度であり、2 つの特徴量の効果は重なっている。

集合の特徴量による MAP の向上は、ケースによって異なる。正解式が 1 本のケースでは $+0.003$ であり（比べる相手の式がない）、2 本以上のケースでは、どの本数でも $+0.064$〜$+0.098$ である（10 通りすべてで上回った）。入力変数の数で分けると、3 個以下で $+0.007$、4〜6 個で $+0.038$、7 個以上で $+0.074$〜$+0.090$ である。

各特徴量への依存の度合いは、訓練し直さない方法でも調べた。訓練済みのモデル（10 個の特徴量、一括の並べ直し）を固定したまま、テストのケースごとに、ある特徴量の値を候補どうしで無作為に入れ替え（シャッフル）、Recall@20 と MAP がどれだけ下がるかを測る（permutation feature importance, PFI）。入れ替えは 20 回行なって平均した。図~\ref{fig:pfi} にシャッフル後の Recall@20 を示す。変数の重複率を測る 6 特徴量（$x_2$、$x_4$〜$x_6$、$x_8$、$x_9$）をまとめてシャッフルすると、Recall@20 は 0.981 から 0.020 に、MAP は 0.860 から 0.010 に下がる（10 通りすべてで下がった）。1 個ずつでは、式の特化度をシャッフルしたときの低下が最も大きい（Recall@20 で 0.981 から 0.127）。話題の近さを測る 4 特徴量（$x_1$、$x_3$、$x_7$、$x_{10}$）は、まとめてシャッフルすると Recall@20 が 0.973、MAP が 0.846 になる。低下は 0.008 と 0.014 と小さいが、10 通りすべてで下がった。特徴量を足して訓練し直す方法（アブレーション）と、訓練済みモデルの入力を入れ替える方法（PFI）は、同じ結論になった。精度の大半を決めているのは変数の重複率を測る特徴量であり、話題の近さを測る特徴量の寄与は小さい。

\section{結果 4：話題の近さを測る特徴量は効かない}\label{sec:topic}

話題の近さを測る 4 特徴量は、加えても精度をほとんど上げなかった（設定 A）。基本の 2 特徴量（$x_1$ と $x_2$）に分野ラベルの一致 $x_7$ を加えると、Recall@20 は $+0.004$（10 通り中 3 通りで上回った）、潜在意味類似度 $x_3$ を加えると $-0.012$（2 通り）であった。基本の 7 個に分野ラベルの一致度（集合）$x_{10}$ を加えると、Recall@20 は $-0.0005$（5 通り）、MAP は $+0.013$（10 通りすべて）であった。分野ラベルをまとめて粗くしても効かなかった。表記の違い（大文字と小文字、記号、複数形）をそろえて 1{,}958 種にした場合と、ラベルの TF-IDF ベクトルを k-means 法で 100 群と 40 群にまとめた場合に、$x_7$ を加えたときの Recall@20 の変化は、それぞれ $+0.007$、$+0.001$、$-0.008$ であった（どれも上回ったのは 10 通り中 3〜4 通り）。なお、10 月 12 日版の k-means の実験は、$x_7$ がほとんど常に 0 になる作りになっていて、ラベルをまとめた効果を測れていなかったので、作り直した。

10 月 12 日版では、効かない原因として、第 1 段の検索の後では候補の話題がそろうことと、候補の選び方が見かけの逆相関を作ることを挙げた。どちらも、候補を 50 件に絞っていたときに起きていたもので、$N_1 = 2{,}000$ ではほとんど消える。1 つの特徴量だけで、正解式と不正解式をどれだけ分けられるかを、AUC で調べた（MLP は使わない）。ケースごとに、正解式と不正解式の組をすべて作り、正解式の値の方が大きい組の割合（値が同じ組は 1/2 と数える）を求め、1{,}731 ケースで平均した。不正解式をデータベースの全式からとる場合と、第 1 段の候補 2{,}000 件の中からとる場合を比べる（表~\ref{tab:auc}）。潜在意味類似度の AUC は、全データベースに対して 0.948、候補の中でも 0.910 であり、候補の中でも正解式を見分けている（候補を 50 件に絞ったときは 0.594 であった）。また、候補の中での文章類似度と変数の一致度の相関係数は $-0.026$ であった（乱数の種 42 の分割、テストの 408 ケース。候補 50 件のときは $-0.404$）。

それでも話題の特徴量が効かないのは、変数の重複率を測る特徴量だけで、候補の中の正解式と不正解式がほとんど分けられるためと考えられる。候補の中での AUC は、変数の一致度で 0.995、式の特化度で 0.994 であり、話題の特徴量（潜在意味類似度 0.910、文章類似度 0.848）より高い。分野ラベルの一致度（集合）の PFI をケースごとに分けても、候補の中で正解式の方が値の高いケース（1{,}332 件）で MAP が 0.003 下がり、不正解式の方が高いケース（255 件）で 0.002 上がるだけであった。10 月 12 日版で見えていた、2 つの群で効く向きが逆になって打ち消し合う様子は、どちらの群でも効きが小さいので、ほとんど見えなくなった。

\section{結果 5：誤りの分析}\label{sec:error}
%======================================================================
\subsection{誤りはどこで生まれるか}\label{sec:errwhere}
1 つの分割（乱数の種 42。テストのケース 408 件、正解式は延べ 1{,}624 本。この分割の Recall@20 は 0.974 で、10 通りの平均 0.981 より低い）で、提案手法（一括の並べ直し）の上位 20 件に入らなかった正解式は 85 本あった。候補 $N_1 = 2{,}000$ 件には正解式がすべて入っているので、85 本はすべて第 2 段の並べ方で漏れたものである。正解式をすべて上位 20 件に並べられたケース（368 件）と、そうでないケース（40 件）を比べると、正解式の数は平均 3.55 本と 7.90 本、入力変数は 14.1 個と 25.8 個であった。上位 20 件に入らなかった正解式と、それより上位にあった不正解式の組をすべて作ると、正解式の値の方が大きい組の割合は、潜在意味類似度で 0.46、文章類似度で 0.48、式の特化度で 0.52、変数の一致度で 0.33 であった。どの特徴量でも 0.5 前後かそれ以下なので、この誤りは、今ある特徴量では直せない。

\subsection{第 2 段の誤りの 2 つの型}\label{sec:errtypes}
\textbf{型 1：別の出典の同じ式}。標準的な式は複数の文献に載るので、正解式と同じ式を、別の出典から選ぶことがある（例：回分発酵のケースで、正解の $\mathrm{d}X/\mathrm{d}t = \mu X$ の代わりに、別の文献に載った同じ式が上位に来た）。評価では式を ID で区別するので、これは不正解と数えるが、利用者にとっては同じ式であり、使える式を提示できている。正解式 3{,}132 本のうち 386 本（12.3\%）は、空白と、\LaTeX{} の間隔や括弧の大きさの命令を除いて同じ文字列の式が、別の出典にもある。このような式を正解とみなすと、設定 A の MAP は、一括の並べ直しで 0.860 から 0.879、逐次選択（訓練も逐次）で 0.874 から 0.904 に上がる（\S\ref{sec:overall}）。

\textbf{型 2：式の向き}。特徴量は変数の集合しか見ないので、同じ変数から別の変数を決める 2 本の式（例：線形化した反応器の $\mathrm{d}C_A'/\mathrm{d}t$ の式と $\mathrm{d}T'/\mathrm{d}t$ の式）は、すべての特徴量で同じ値になる。こちらは利用者にとっても誤りである。どの変数を決める式かを表す特徴量が要る。

%======================================================================
\section{現時点の限界}\label{sec:limits}
%======================================================================
\begin{itemize}[leftmargin=1.5em]
  \item 合成のケースの説明文は LLM が書いたもので、人が書く依頼文と文体が違う可能性がある（式と入出力変数はプログラムで決まる）。単一出典の正解集合は、LLM が最小と判断した組であり、最小かどうかは確かめていない。
  \item 変数は記号だけで照合し、定義の文章を使わない。評価ケースの正解集合のうち 1{,}300 件では、2 本以上の正解式に現れる記号の定義の文章が式によって違う。多くは言い換えであるが、LLM（Claude Opus 5.5）に定義を比べさせると、596 件で、入出力変数の記号が式によって別の量を指すと判定された（人は確かめていない）。
  \item 評価はデータベースの中の式だけで行なっており、データベースにない式は検索できない。
  \item 検索手法の正解は ID で判定するので、別の出典の同じ式を選ぶと不正解と数える（同じ式を正解とみなした結果も示した。\S\ref{sec:overall}）。データベースには、同じ文献が複数の出典として入っているもの（36 文献）や、別の文献に載った同じ式があり、実際にデータベースを作るときには重複を除く必要がある。
  \item 文献は人の目で選別しておらず、物理モデルと関係の薄い文献も含まれる。初期の 9 報は、版の記録がない Gemini で式を抽出した。
  \item 変数の重複率を測る 6 特徴量だけで、精度の大半が決まる（まとめてシャッフルすると Recall@20 が 0.961 下がる）。どのケースも入出力変数を正解式の変数記号から選んでおり、クエリと正解式が同じ表記を使うという本データの作り方も、これに効いている。表記の違うクエリに対して同じ精度が出るかは確かめていない。
  \item 逐次選択の訓練は teacher forcing であり、訓練では正解式を、推論では自分が選んだ式（誤りを含みうる）を参照集合にする。この食い違いは残っている。
  \item ハイパーパラメータのうち、参照集合の大きさ $m$、マージン $\gamma$、不正解の抽出数 $n_{\mathrm{neg}}$、エポック数、学習率は、ほかの値と比べていない。
  \item LLM との比較は、まだ結果が出ていない。
\end{itemize}

\section{まとめと今後の課題}\label{sec:summary}
%======================================================================
\textbf{まとめ}：提案手法は、第 1 段の検索で候補を $N_1$ 件に絞り、第 2 段の検索で候補を 10 個の特徴量で並べ直して、上位 20 件を提示する。$N_1$ を、正解式がすべて候補に入る 2{,}000 件にすると、検証用のケースで重みを選んだ古典的情報検索手法と比べ、Recall@20 を設定 A で 0.906 から 0.981 に、設定 B で 0.825 から 0.966 に上げ、MAP を 0.690 から 0.860 に、0.626 から 0.832 に上げた。どの指標でも、10 通りの分割のすべてで上回った。向上は、正解式と入力変数の多いケースで大きい。精度の大半を決めているのは変数の重複率を測る特徴量（特に式の特化度）であり、集合の特徴量は主に上位 20 件の中での正解式の順位を上げる（MAP で $+0.073$）。話題の近さを測る特徴量は、候補の中でも正解式を見分けるが、変数の特徴量に加えても精度をほとんど上げなかった。逐次選択は、正解式が 8 本以上のケースで MAP を $+0.032$ 上げた。上位 20 件に入らない正解式は、すべて第 2 段の並べ方で生まれており、今ある特徴量では直せない。

\textbf{今後の課題}：
\begin{itemize}[leftmargin=1.5em]
  \item LLM との比較を、\S\ref{sec:compared} の方法で行なう。
  \item データベースから重複を除き、評価ケースの説明文と入出力変数の食い違い、記号の意味の食い違いを見直す。
  \item どの変数を決める式かを表す特徴量を設計する（\S\ref{sec:errtypes} の型 2）。
\end{itemize}

\section{LLM に与えたプロンプト}\label{app:prompts}
データとケースを作るのに LLM を使った場面と、そのプロンプトを示す。\texttt{\{ \}} で囲んだ部分には、それぞれの説明に書いたものを差し込んだ。出典横断の 33 件は、コーディング支援に使った LLM（Claude）がプログラムに直接書いたもので、決まったプロンプトはない。拡張ケースの説明文の言い換えと、出典横断のうちプログラムで作ったケースの説明文には、LLM を使っていない。

\subsection{式の抽出（Gemini）}
文献の PDF を添付して送った。\texttt{\{source\_id\}} には PDF のファイル名を入れた。
\begin{Verbatim}[fontsize=\scriptsize, breaklines=true, frame=single]
Extract all numbered equations and equations found in the appendices from this textbook in LaTeX format. For each equation, identify the "variable definitions" and the "physical meaning (context)" from the surrounding text. Output the result in the JSON format specified below.

Constraints:
- Extract the content EXACTLY as it appears in the literature. Do not make unauthorized corrections or modifications.
- Preserve every variable symbol and subscript exactly as printed: e.g. if the source writes c_w (specific heat of water), do NOT change it to c_p; if it writes C_p or Cp, do not change to c_w. Never "normalize" or "standardize" notation.

Output a single JSON array. Each element must have these fields:
- source_id: string (e.g. PDF filename)
- eq_id: string (e.g. "eq_1")
- equation: string (LaTeX form)
- variables: object with variable symbols as keys and their definitions (strings) as values
- context_text: string (surrounding text explaining physical meaning)
- domain: string (process or domain name, e.g. "CSTR Kinetics")


Use source_id = "{source_id}" for all equations from this document.
\end{Verbatim}

\subsection{基礎式集の生成（Gemini 2.5 Pro）}
最初の 1 件（化学工学の基本式 20 本）は次のプロンプトで生成した。
\begin{Verbatim}[fontsize=\scriptsize, breaklines=true, frame=single]
You are an expert in chemical engineering and process modeling.
Generate exactly 20 fundamental equations that are essential for process modeling, in LaTeX format.
Include equations from the following areas:
- CSTR (continuous stirred-tank reactor): mass balance, energy balance, design equation
- Biodiesel production: transesterification kinetics, yield relations
- Mass balance and heat balance (general)
- Reaction kinetics: rate laws, Arrhenius equation, activation energy
- Dimensionless numbers: Reynolds, Nusselt, Prandtl, Damköhler, Peclet, etc.
- Heat transfer: convection, overall heat transfer coefficient
- Fluid mechanics: pressure drop, flow relations

For each equation provide:
- source_id: use exactly "handbook_chemeng"
- eq_id: "eq_1" through "eq_20"
- equation: LaTeX form of the equation
- variables: object with each variable symbol as key and its definition (string) as value
- context_text: brief physical meaning or context (one or two sentences)
- domain: short domain name (e.g. "CSTR", "Reaction Kinetics", "Heat Transfer")

Output a single JSON array of exactly 20 equation objects. Use the exact field names above.
Do not include any markdown or code fence, only the JSON array.
\end{Verbatim}

残る 31 件は、分野ごとに次のプロンプトで生成した。\texttt{\{label\}} には分野の名前、\texttt{\{n\}} には式の本数、\texttt{\{topics\}} には分野ごとに決めた話題の一覧、\texttt{\{source\_id\}} には基礎式集の名前を入れた。
\begin{Verbatim}[fontsize=\scriptsize, breaklines=true, frame=single]
You are an expert in {label} and mathematical modeling.
Generate exactly {n} fundamental equations used in {label}, in LaTeX format.

Cover these topics:
{topics}

For each equation provide:
- source_id: use exactly "{source_id}"
- eq_id: "eq_1" through "eq_{n}" (sequential)
- equation: LaTeX form of the equation (use standard notation)
- variables: object with each variable symbol as key and its definition (with units where appropriate) as value
- context_text: brief physical meaning or context (1-3 sentences, include when and where this equation is used)
- domain: "{label}" or a more specific sub-domain (e.g., "{label}: Pipe Flow")

IMPORTANT:
- Each equation MUST be distinct (no duplicates).
- Include both the differential form and algebraic form where applicable.
- Use standard notation conventions for the field.
- Variables dict must include ALL symbols that appear in the equation.

Output a single JSON array of exactly {n} equation objects. No markdown fences.
\end{Verbatim}

\subsection{単一出典のケースの生成（Gemini 2.5 Pro）}
\texttt{\{catalog\_text\}} には、その回の式の一覧（式ごとに ID、出典名、出典内の番号、分野ラベル、変数記号の一覧）を JSON で入れた。\texttt{\{domain\_list\}} にはその回の分野ラベル（先頭の 20 個）、\texttt{\{n\_cases\}} には作らせる件数（13）を入れた。
\begin{Verbatim}[fontsize=\scriptsize, breaklines=true, frame=single]
You are helping to create training data for a graph neural network that selects
relevant equations for physical process modeling.

You are given a catalog of equations. Each equation has:
- model_id: a unique ID in the form "<source_id>__<eq_id>"
- domain: a short domain label
- variable_symbols: list of variable symbols in the equation

CATALOG ({len(batch_catalog)} equations, domains: {domain_list}):
{catalog_text}

TASK:
Using ONLY the models listed above, create approximately {n_cases}
realistic and physically meaningful core training cases.

For each core case:
- Pick one or more model_ids that together represent a coherent physical model.
- Define a context string describing the physical scenario in natural language.
- Choose input_variables and output_variables from variable_symbols of selected models.
- correct_model_ids: list of model_ids forming a correct mathematical model.

CONDITIONS FOR correct_model_ids:
(1) Given input_variables values and the equations, it MUST be possible to solve for all output_variables.
(2) The equation set MUST be sufficient and minimal (no redundant equations).

REQUIREMENTS:
- All correct_model_ids MUST exactly match entries from the catalog.
- input/output variables MUST be subsets of variable_symbols from selected models.
- Make cases diverse across the available domains.
- Generate at least {n_cases} cases.

OUTPUT: JSON object with "cases" array, each having:
case_id, context, input_variables, output_variables, correct_model_ids
\end{Verbatim}

\subsection{合成のケースの説明文（Claude Sonnet 4.5）}
\texttt{\{eqs\_str\}} には、正解式ごとに出典名、出典内の番号、分野ラベル、式の表記（先頭の 200 文字）を 1 行ずつ入れた。入力変数は名前の順に先頭の 10 個を、変数の定義は出力変数と一部の入力変数について最大 10 行を入れた。
\begin{Verbatim}[fontsize=\scriptsize, breaklines=true, frame=single]
You are a chemical engineering expert. Given a set of equations from
literature, and specified input/output variables, write a concise physical
scenario description (2-3 sentences) in English describing the modeling task.

EQUATIONS:
{eqs_str}

INPUT VARIABLES (known): {sorted(inputs)[:10]}
OUTPUT VARIABLES (to be solved): {sorted(outputs)}

VARIABLE DEFINITIONS (excerpt):
{var_defs_str}

Write a 2-3 sentence description of the physical modeling scenario. Focus on:
- What system is being modeled (reactor, heat exchanger, etc.)
- What is computed (the outputs) given the inputs
- The physical meaning of the coupled equations

Output only the description, no preamble or formatting.
\end{Verbatim}

\subsection{出典横断の説明文の書き直し（Claude Opus 4.8）}
入出力変数を選び直した 111 件と、説明文が出力変数と合っていなかった元のケース 2 件のそれぞれについて、元のケースの説明文、元の出力変数、新しい出力変数、元の出力変数のうち新しく入力変数になったもの（now\_given）を JSON で渡した（元のケース 2 件では、元の出力変数と新しい出力変数は同じ）。変数には、記号と、正解式での定義を付けた。指示（システムプロンプト）は次のとおりである。
\begin{Verbatim}[fontsize=\scriptsize, breaklines=true, frame=single]
You edit the problem descriptions of an evaluation set for retrieving process-model equations.
A description states, in plain words, a physical system and which quantities must be determined.

You receive a description written for one choice of quantities to determine (original_outputs) and a new choice for the same system (new_outputs). "now_given" lists the quantities that the original asked to determine but that are now given. Each quantity comes with its symbol and its meaning taken from the source equations. Rewrite the description for the new choice.

Rules:
- Describe the same physical system and keep the original wording, changing only what the new choice requires.
- State every quantity in new_outputs as a quantity to determine.
- The original may ask, explicitly or implicitly, to determine quantities that are not in new_outputs, including quantities that are not variables of the system at all (for example, "size a reactor" asks for its volume). Remove or reword every such request, so that only the quantities in new_outputs are to be determined. This applies even when new_outputs equals original_outputs.
- Present every quantity in now_given as given. Do not name any other quantity as given unless the original already names it.
- Never present a quantity in new_outputs as given.
- Refer to quantities in plain words by their meaning, as the original does. Do not write symbols or equations.
- Do not add information beyond the original description and the meanings of the quantities.
- Write one or two sentences in English, as short as the changes allow.

Return JSON: {"context": "<the rewritten description>"}.
\end{Verbatim}

\subsection{LLM との比較（4 つのモデルに共通）}
system とした指示文と、データベース、テストケースを、この順に送った。データベースの部分は、すべての呼び出しで同じなので、プロンプトキャッシュを使った。出力は、式の ID の列を JSON の形で返させた。
\begin{Verbatim}[fontsize=\scriptsize, breaklines=true, frame=single]
[system]
You are an expert in physical modeling. You select equations from an equation database for building a physical model.

# Task
An engineer wants to build a physical model: a set of equations with which the output variables can be computed once the input variables are given. The engineer describes the model and lists its input variables and output variables. Choose, from the equation database, the equations that the engineer should use.

The set of equations that forms the model satisfies these conditions:
1. Every input variable and every output variable appears in at least one equation of the set.
2. The number of equations equals the number of variables of the set that are not input variables.
3. Every variable of the set that is neither an input nor an output variable appears in at least two equations of the set.

# Equation database
<equation_database> lists equations extracted from the literature, in no particular order. Each line has three fields separated by tabs: the equation ID, the domain label of the equation, and the equation in LaTeX.

# Answer
For the task in <task>, list up to 20 equation IDs, from the most to the least likely to belong to the model. Put first the equations that you judge to form the model. If they are fewer than 20, continue with the other equations most likely to be needed for this model, until the list has 20 IDs. Use only IDs from the database, and list each ID once. In the task, variable symbols in a list are separated by " ; ".

[user, block 1: データベース（cache_control: ephemeral）]
<equation_database count="11146">
1	<分野ラベル>	<式の表記（LaTeX、空白を 1 個にまとめただけ）>
2	...
...
</equation_database>

[user, block 2: テストケース]
<task>
Description: <説明文>
Input variables: <記号> ; <記号> ; ...
Output variables: <記号> ; ...
</task>

List the IDs of the database equations for this task.
\end{Verbatim}
