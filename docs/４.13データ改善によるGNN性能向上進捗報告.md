## 1. 研究目的

科学文献PDFから数式を自動抽出し、自然言語で記述されたプロセス条件（例：「CSTRの定常濃度を求めたい。入力は流量と反応速度定数」）に対して、最適な物理モデル（数式の集合）を自動選択するRetrievalシステムを開発する。数式間の変数共有関係をグラフ構造で表現し、グラフニューラルネットワーク（GNN）ベースの検索手法の有効性を検証する。

## 3. 情報抽出手法

### 3.1 PDF→数式の構造化抽出

**使用モデル**: Google Gemini 2.5 Pro（Structured Output モード）

PDFファイルをGemini APIにアップロードし、以下のプロンプトで数式を構造化JSONとして抽出する。出力スキーマはPydanticモデルで定義し、`response_json_schema`パラメータで型安全なJSON出力を強制している。

**入力**: PDF文書ファイル
**出力**: 数式のJSON配列（各要素: source_id, eq_id, equation, variables, context_text, domain）

**抽出プロンプト**:
```
Extract all numbered equations and equations found in the appendices
from this textbook in LaTeX format. For each equation, identify the
"variable definitions" and the "physical meaning (context)" from the
surrounding text.

Constraints:
- Extract the content EXACTLY as it appears in the literature.
  Do not make unauthorized corrections or modifications.
- Preserve every variable symbol and subscript exactly as printed:
  e.g. if the source writes c_w (specific heat of water),
  do NOT change it to c_p; if it writes C_p or Cp, do not change to c_w.
  Never "normalize" or "standardize" notation.

Output a single JSON array. Each element must have these fields:
- source_id: string (e.g. PDF filename)
- eq_id: string (e.g. "eq_1")
- equation: string (LaTeX form)
- variables: object with variable symbols as keys and their definitions as values
- context_text: string (surrounding text explaining physical meaning)
- domain: string (process or domain name, e.g. "CSTR Kinetics")
```

**Gemini無料枠制約**:
- **レート制限**: 5 RPM（12秒間隔で呼び出し）
- **ページ上限**: Gemini APIは約1,000ページが上限 → pypdfで80ページ単位に分割（3冊の大型テキストブック、39チャンク）

### 3.2 ハンドブック式のLLM生成

**入力**: ドメイン名、トピックリスト、生成式数
**出力**: 数式のJSON配列（抽出と同一スキーマ）

**生成プロンプト**:
```
You are an expert in {domain_label} and mathematical modeling.
Generate exactly {n} fundamental equations used in {domain_label}, in LaTeX format.

Cover these topics:
{topics}

For each equation provide:
- source_id: use exactly "{source_id}"
- eq_id: "eq_1" through "eq_{n}" (sequential)
- equation: LaTeX form of the equation (use standard notation)
- variables: object with each variable symbol as key and its definition as value
- context_text: brief physical meaning or context (1-3 sentences)
- domain: "{label}" or a more specific sub-domain

IMPORTANT:
- Each equation MUST be distinct (no duplicates).
- Include both the differential form and algebraic form where applicable.
- Use standard notation conventions for the field.
- Variables dict must include ALL symbols that appear in the equation.
```

**トピックリストの例（流体力学の場合）**:

## 4. グラフ構築とGNN学習

### 4.1 二部グラフの構築

数式と変数の関係を二部グラフとして表現する。

| 項目 | 値 |
|------|-----|
| 数式ノード | 3,244 |
| 変数ノード | 3,704 |
| 二部エッジ | 33,638（双方向） |
| ノード特徴量 | 768次元（CodeBERT [CLS] 埋め込み） |

**ノード特徴量の計算**:
- **数式ノード**: `"Equation: {LaTeX}\nContext: {context_text}"` をCodeBERT（microsoft/codebert-base）に入力し、[CLS]トークンの768次元埋め込みを使用
- **変数ノード**: その変数を含む全数式のCodeBERT埋め込みの平均

**エッジの定義**: 数式 i が変数 j を含む場合、(i, j) と (j, i) の双方向エッジを張る。数式間の間接的な関連は、変数ノードを介した2ホップのパスとして表現される。

### 4.2 GNNアーキテクチャ

2種類のGNNベースアプローチを実装した。

#### (A) GCN Retriever

| コンポーネント | 構成 |
|---------------|------|
| 数式エンコーダ | 2層GCN（GCNConv 768→768→768, Dropout 0.1） |
| クエリエンコーダ | TF-IDF→SVD(256次元)→MLP(256→512→768, ReLU, Dropout 0.1) |
| 損失関数 | Sampled InfoNCE（温度 τ=0.07） |
| 負例数 | 64 / ケース |
| 最適化 | AdamW (lr=2e-3, weight_decay=1e-4) |
| エポック数 | 3 |

#### (B) 残差GCN SVD洗練

TF-IDF+SVDの強いベースライン埋め込みを出発点とし、GCNで残差的に洗練する。

| コンポーネント | 構成 |
|---------------|------|
| ベースライン埋め込み | TF-IDF→SVD(256次元)→L2正規化 |
| GCN Refiner | 2層GCN(256→256→256) + 学習可能な混合パラメータ α |
| 出力 | $E_{\text{refined}} = \text{L2norm}(x + \alpha \cdot h)$（αは0で初期化） |
| 損失関数 | Sampled InfoNCE（温度 τ=0.07） |
| 負例数 | 128 / ケース |
| エポック数 | 10 |

#### (C) 2段階リランカー　← 主要手法

Stage 1でTF-IDF+Jaccardにより候補50件を抽出し、Stage 2でMLPリランカーが特徴量ベクトルに基づきリランキングする。

**Stage 1: 候補抽出（固定重み）**

$$\text{score} = 0.7 \times \text{TF-IDF cosine} + 0.3 \times \text{Jaccard}(IO_{\text{query}}, V_{\text{eq}})$$

上位50件を候補として抽出。

**Stage 2: MLP リランカー**

```
入力(n次元) → Linear(64) → ReLU → Dropout(0.1)
           → Linear(64) → ReLU → Dropout(0.1)
           → Linear(1) → Sigmoid
```

| ハイパーパラメータ | 値 |
|------------------|-----|
| 隠れ層 | 64次元 × 2層 |
| 損失関数 | マージンランキング損失（margin=0.1） |
| 負例数 | min(8, 利用可能数) / 正例 |
| バッチサイズ | 16 |
| エポック数 | 15 |
| 最適化 | AdamW (lr=1e-3, weight_decay=1e-4) |

### 4.3 特徴量の設計

#### ベース7特徴量（reranker-7）

| # | 特徴量名 | 計算方法 |
|---|---------|----------|
| 0 | テキスト類似度 | TF-IDF cosine(クエリcontext, 式のcontext+equation+domain) |
| 1 | I/O変数Jaccard | Jaccard(クエリ入出力変数, 式の変数集合) |
| 2 | SVD埋め込み類似度 | TF-IDF→SVD(256次元)空間でのcosine類似度 |
| 3 | 入力変数カバー率 | \|input\_vars ∩ eq\_vars\| / \|input\_vars\| |
| 4 | 出力変数カバー率 | \|output\_vars ∩ eq\_vars\| / \|output\_vars\| |
| 5 | 式変数中のクエリ割合 | \|IO\_set ∩ eq\_vars\| / \|eq\_vars\| |
| 6 | ドメイン一致 | クエリcontextと式domainの部分文字列一致（0/1） |

#### クエリ条件付きグラフ特徴量（reranker-10で追加される3次元）

| # | 特徴量名 | 計算方法 | 捉える情報 |
|---|---------|----------|-----------|
| 7 | 2ホップ到達率 | クエリI/O変数のうち、変数共有グラフ上で候補式に2ホップ以内で到達可能な割合 | 間接的な変数関連 |
| 8 | グラフ近傍重複度 | Jaccard(候補式のグラフ近傍式集合, クエリ変数を含む式集合) | 構造的近接性 |
| 9 | 間接変数ブリッジ比率 | 候補式の変数のうち、クエリ変数には含まれないが、クエリ変数を持つ他式にも出現する変数の割合 | 隠れた接続 |

**核心**: これら3特徴量はすべて**クエリに条件付き**（同じ候補式でもクエリごとに異なる値をとる）。クエリに依存しない固定GNN埋め込みとは本質的に異なるアプローチである。

## 6. 考察

### 6.1 データ規模がグラフ構造の価値を決定する

本研究の最も重要な発見は、グラフ特徴量の有効性がデータ規模に明確に依存するスケーリング則である。

- **975式（スパースグラフ）**: 変数ノードの次数が低く、2ホップ到達率がほぼ0/1に二値化。グラフ特徴量はリランカーにノイズを注入し、性能を悪化させた（ΔMRR = −0.006）。
- **1,613式（遷移領域）**: グラフがやや密になり、グラフ特徴量が微小ながら正の寄与を示すようになった（ΔMRR = +0.006）。
- **3,244式（密グラフ）**: 変数ノードの次数が十分に増加し、2ホップ到達率・近傍重複度が連続的な値をとるようになった。グラフ特徴量が候補間の有意な差別化を可能にし、全手法中最高性能を達成（ΔMRR = +0.012）。

この結果は、グラフ構造特徴量には一定のデータ密度の閾値が存在し、約1,600式/2,000変数付近に転換点があることを示唆する。

### 6.2 クエリ条件付きグラフ特徴量の有効性

初期に試行したクエリに依存しないGNN埋め込み（GCN Retriever、残差GCN SVD洗練）はいずれもベースラインを超えられなかった。一方、クエリの入出力変数に条件付けしたグラフ特徴量は、十分なデータ規模のもとで有効に機能した。

これは、数式retrievalにおいて「どの変数を介してグラフ上で関連しているか」がクエリごとに異なるため、固定的な埋め込みでは捉えきれない情報があることを示唆する。

### 6.3 語彙的手法の頑健性とグラフの補完的役割

TF-IDF + Jaccardベースラインは3,244式でMRR 0.924を達成しており、極めて強い。学習型手法のマージンは+1.3%（reranker-7）〜+2.5%（reranker-10）である。

グラフ特徴量は語彙的手法を**置き換える**のではなく**補完する**ものとして機能しており、2段階アーキテクチャ（語彙的候補抽出 → グラフベースリランキング）の妥当性が示された。

### 6.4 分散の縮小

データ拡大により、全手法で5 seed間の分散が大幅に縮小した（baseline: 0.088→0.040、reranker-7: 0.119→0.018）。これは評価の統計的信頼性の向上を意味し、データの多様性がモデルの安定性にも寄与することを示す。
