\section{Problem Formulation}
\label{sec:formulation}

In this thesis a physical model is a set of equations from which the output variables can be
computed once the input variables are given. Kato and Kano formulated model building from
documents as the combination of extracted equations, and they defined four requirements that the
equation set $S$ of a desired model must meet\cite{CombineEq}. Let $\mathcal{I}$ and $\mathcal{O}$
be the input and output variables, and let $V(S)$ be the variables that appear in the equations
of $S$.
% 要件の名称: 原典の要旨（OpenAlex 収録、2026-10-12 確認）が挙げる名称は "input–output completeness and
%   consistency" のみ。要件 1 は要旨の語、要件 2〜4 は内容に沿った呼び名（内容は日本語版報告 §2.1 と同じ）。
\begin{enumerate}
  \item Input--output completeness: every input and output variable appears in $S$, that is,
    $\mathcal{I} \cup \mathcal{O} \subseteq V(S)$.
  \item Degree-of-freedom consistency: the degrees of freedom of $S$, the number of variables minus
    the number of equations\cite{Seborg},
    \begin{equation}
      N_{\mathrm{DoF}}(S) = |V(S)| - |S| ,
      \label{eq:dof}
    \end{equation}
    equal the number of input variables, $N_{\mathrm{DoF}}(S) = |\mathcal{I}|$. Under
    requirement~1 this is equivalent to $|V(S) \setminus \mathcal{I}| = |S|$: once the inputs are
    given, $S$ has exactly as many unknown variables as equations.
  \item Solvability: every variable other than the input and output variables appears in at least
    two equations of $S$.
  \item Unique constant equations: each variable that represents a constant is defined by a single
    equation that sets it to that constant.
\end{enumerate}
The four requirements are necessary conditions; a set that meets them need not serve as a
model\cite{CombineEq}.

The combination method of Kato and Kano takes a given set of equations and returns every
combination that meets the requirements. This study instead searches a large database built from
many documents and presents the equations most likely to serve in the requested model; the
engineer assembles and checks the model from them. A query is a triple
$q = (c, \mathcal{I}, \mathcal{O})$, where the description $c$ states the desired model in natural
language and $\mathcal{I}$ and $\mathcal{O}$ list the symbols of the input and output variables; we
write $\mathcal{Q} = \mathcal{I} \cup \mathcal{O}$ for the query variables. The database
$\mathcal{E} = \{e_1, \dots, e_N\}$ stores for each equation $e_j$ its \LaTeX{} expression, its
variable set $V(e_j)$ with a definition of each symbol, a context text that explains the physical
meaning of the equation, its source, and a domain label $\mathrm{dom}(e_j)$ that names the field
or process in free text; the extracting language model writes the context text from the passage
around the equation and chooses the domain label freely (Section~4.1). Two variables are the same only when their
symbols match exactly, both between the query and an equation and between two equations. The
method outputs a ranking of the database and presents its top equations, and
Section~\ref{sec:dofstop} decides how many.
% source: extract_equations.py EXTRACTION_PROMPT（context_text: "surrounding text explaining physical
%         meaning"）, extract_equations_claude.py（"1-3 sentences describing the physical meaning ... based on
%         its surrounding context"）; two_stage_query_conditioned.py norm() は strip() のみ（記号の正規化なし）

To evaluate the method, each test case designates one ground-truth set
$\mathcal{R}_q \subset \mathcal{E}$, the equations of the requested model (Section~4.2). We call the
equations in $\mathcal{R}_q$ correct and all other equations incorrect, and we write
$K = |\mathcal{R}_q|$ for the answer size. Equations are identified by an identifier that combines
the source and the equation number, so an equation identical to a correct one but taken from
another source counts as incorrect (Sections~\ref{sec:metrics} and~\ref{sec:erroranalysis}).

\section{Stage 1: Candidate Retrieval}
\label{sec:stage1}

The first stage scores every equation in the database independently and keeps the top $k$ as
candidates. The score mixes one text term and one variable term,
% source: two_stage_query_conditioned.py stage1() L248-254（w_text*ts + w_var*vs, argsort 上位 k）;
%         eq_text() L71（context_text・equation・domain を連結）
\begin{equation}
  s_1(q, e_j) = w_{\mathrm{t}} \cos\!\big(\mathrm{tfidf}(c), \mathrm{tfidf}(t_j)\big)
              + w_{\mathrm{v}} \, J\!\big(\mathcal{Q}, V(e_j)\big) ,
  \label{eq:stage1}
\end{equation}
where $t_j$ joins the context text, the expression, and the domain label of equation $e_j$,
$J(A, B) = |A \cap B| / |A \cup B|$ is the Jaccard similarity, the
term-frequency--inverse-document-frequency (TF-IDF) vectors\cite{Salton} use word unigrams and
bigrams over a vocabulary built from all $t_j$, and the weights $w_{\mathrm{t}}$ and $w_{\mathrm{v}}$
balance the text similarity against the variable overlap. Chapter~5 gives the values of $k$ and of
the weights. Ranking the whole database by Eq.~\eqref{eq:stage1} is a classical
information-retrieval method\cite{Manning}, and Chapter~5 uses it, without a learned model or a
candidate window, as the baseline; the second stage reranks only the $k$ candidates it receives.

The second stage cannot recover a ground-truth equation that the first stage leaves out, so the
fraction of ground-truth equations among the candidates --- the candidate coverage --- bounds what
the second stage can achieve. The coverage depends on both the window $k$ and the weights, and we
measure it because it separates the two error sources that Chapter~6 analyses: equations the first
stage never proposes, and equations the second stage proposes but ranks too low.

\section{Stage 2: Set-aware Reranking}
\label{sec:stage2}

The second stage judges each candidate not on its own but against the equations already at hand.
Table~\ref{tab:features} lists the ten features it uses. Seven of them compare the query with a
single equation: two measure topical closeness of the description ($f_1$, $f_3$), one matches the
domain label against the description ($f_7$), and four measure how the equation's variables relate
to the query variables ($f_2$, $f_4$, $f_5$, $f_6$). The remaining three are the set-aware features
that this study introduces. They are computed against a reference set $R$, which is the top
$K_{\mathrm{ref}}$ candidates of Stage 1 during static scoring and the already selected
equations during sequential selection (Section~\ref{sec:seq}); a candidate that belongs to $R$ is
excluded from its own reference set.
% source: set_aware_reranker.py K_REF=5 L95, compute_set_aware_features L119-137（自己除外）

Complementarity $g_{\mathrm{Comp}}$ asks what the candidate adds: it is the fraction of query
variables that appear in the candidate but in no equation of the reference set. Coherence
$g_{\mathrm{Coh}}$ asks whether the candidate connects to what is already selected: it is the
fraction of the candidate's variables shared with the reference set. Domain agreement
$g_{\mathrm{Dom}}$ asks whether the candidate comes from the same topic as the reference set: it is
the fraction of reference equations whose domain label equals the candidate's. The first two
encode how equations determine one another's variables, the third encodes topical consistency, and
Section~\ref{sec:mechanism} shows that only the first two contribute.

The latent similarity $f_3$ deserves one remark. We factorize the TF-IDF matrix of all equation
texts with a truncated singular-value decomposition (SVD)\cite{LSA} into 256 dimensions, project the query
into the same space, and take the cosine similarity. Unlike $f_1$, the query text here also lists
the input and output variable names, so $f_3$ sees both the description and the requested
variables.
% source: two_stage_query_conditioned.py case_text(c, io=True) → svd クエリ; 256 成分

A multilayer perceptron (MLP) maps the ten features to a score. It has two hidden layers of 64
units with rectified-linear activation and dropout 0.1.
% source: two_stage_query_conditioned.py class Reranker L197-205（Linear-ReLU-Dropout ×2 + Linear）
We train it with a pairwise ranking loss\cite{LTR}: for each ground-truth equation $e^{+}$ among
the candidates of a training case and each of eight incorrect candidates $e^{-}$ sampled at
random from the same case,
\begin{equation}
  \ell(e^{+}, e^{-}) = \max\!\big(0,\; \gamma - \mathrm{MLP}(x(q, e^{+})) + \mathrm{MLP}(x(q, e^{-}))\big),
  \qquad \gamma = 0.1 ,
  \label{eq:loss}
\end{equation}
where $x(q, e)$ is the feature vector. We optimize with AdamW (learning rate $10^{-3}$, weight
decay $10^{-4}$) for 15 epochs over batches of 16 cases. Appendix~A lists every hyperparameter. We
call this configuration reranker-10S, and reranker-7 for the variant that drops the three
set-aware features.

\section{Sequential Selection}
\label{sec:seq}

Because the set-aware features depend on what has already been selected, the reference set used
during training need not match the one used at inference. We therefore compare three strategies and
isolate the effect of that mismatch.

Static scoring computes the set-aware features once against the Stage-1 top-$K_{\mathrm{ref}}$
reference and ranks all candidates by a single forward pass. Greedy selection at inference builds
the answer one equation at a time: it takes the candidate with the highest static score first,
recomputes the set-aware features of the remaining candidates against the equations selected so
far, takes the highest-scoring one, and repeats until it has selected 20 equations or exhausted
the candidates; the unselected candidates follow in the order of their static scores. The model
itself is trained statically.
% source: set_aware_reranker.py greedy_order L213-243（先頭は静的スコア最大、以降は再計算、
%         greedy_cap=20、残りは init_scores 順）
Learned greedy additionally \emph{trains} on the same sequential contexts with teacher forcing: at
step $t$ the true partial answer serves as the reference set, and the loss pushes the next
ground-truth equation above the sampled negatives. Training then asks the same question as
inference, namely which equation to select next, given the ones already chosen.
% source: set_aware_reranker.py run_mode の train_greedy ブロック L440-470（teacher forcing・
%         t=0 は静的参照で「種」を学習・greedy_train_cap=8）
Teacher forcing keeps training stable but leaves a train--test gap, because at inference the
reference set may contain mistakes; Section~\ref{sec:limitations} returns to this point.

\section{Self-terminating Retrieval}
\label{sec:dofstop}

Ranking assumes the caller knows how many equations to take. An engineer does not know the answer
size $K$ in advance, so we let retrieval stop by itself. DoF-stop extends greedy selection: after
each selection it checks whether the selected set $S$ meets two conditions,
\begin{equation}
  \text{(a)}\;\; \mathcal{O} \subseteq V(S)
  \qquad\text{and}\qquad
  \text{(b)}\;\; |V(S) \setminus \mathcal{I}| \le |S| ,
  \label{eq:stopcond}
\end{equation}
and it stops and returns $S$ at the first length where both hold. Condition~(a) is the output part
of requirement~1, and condition~(b) relaxes the equality of requirement~2 to an inequality. When no
prefix meets the conditions within the selection cap of 20 equations, DoF-stop returns the 20 it
selected.
% source: set_aware_reranker.py greedy_close L246-291（closed() = 出力被覆 かつ |covered − input_v| <= |sel|、
%         greedy_cap=20、閉じなければ選択総数を返す）

DoF-stop checks neither requirement~3 nor requirement~4, and it does not check whether the
selected equations are independent or consistent, so the set at which it stops need not be
solvable. Counting variables against equations is a necessary check for solvability, not a
sufficient one\cite{Hangos}. Consider a query with $\mathcal{I} = \{x, z\}$ and
$\mathcal{O} = \{y_1, y_2\}$, and the selections $y_1 = x$, $y_1 = x + 1$, and $y_2 = z$ in this
order. After the third selection both conditions hold, since the two unknowns $y_1$ and $y_2$ number
fewer than the three equations, and DoF-stop stops. Yet the two equations for $y_1$ contradict each
other, and $N_{\mathrm{DoF}}(S) = 4 - 3 = 1$ differs from $|\mathcal{I}| = 2$, so the set violates
requirement~2 as well. DoF-stop also selects greedily without backtracking and only among the
first-stage candidates, so it may never meet the conditions --- for instance, when the first stage
has missed an equation that the answer needs. DoF-stop thus decides how many equations to present;
whether the presented equations form a model remains for the engineer to check. Evaluating it
requires set-level measures rather than ranking measures, so Chapter~5 adds the exact-match rate,
the set $F_1$, and the stop-condition rate.
